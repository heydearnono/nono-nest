# 把线上工作台的全部功能迁移到小程序

- 日期：2026-08-11 ~ 2026-08-12
- 场景：产品重定位（P0）+ 数据模型与存储层（P1）
- 参与：Ducc（Opus 5）

## raw prompt

原样保留：

```text
我需要前期先将这个页面内所有的功能迁移到小程序我该怎么做
```

上一轮的上下文只有一条：

```text
https://xiaoluzhu.net/ 可以访问这个地址吗？
```

之后是两条推进指令：`开始做吧`、`继续下一步`。

## 这次 prompt 缺什么

「这个页面内所有的功能」这句话里，**「所有」是不可执行的**。我先把线上 bundle 逆出来才知道
这句话实际覆盖 17 条路由、595 条中文文案、2000 个汉字、169 首古诗、140 个贴纸、11 个成就。
如果按字面「全部迁移」一次做完，就是一个几十个文件的大改，且必然跳过文档先行。

具体缺的三条：

- **仓库归属** —— 在现有 `nono-nest` 上扩，还是新建 `nono-workbench`？
  这条决定要不要重写 `vision.md` / `glossary.md`，工作量差一个数量级。
  我用 `AskUserQuestion` 给了三个候选（扩现有 / 新仓库 / 单域试点），用户选了扩现有 ——
  理由是 Spec ID 门禁、CI、术语表这套机器可以直接复用。
- **语音跟读做不做** —— 线上用 `speechSynthesis` + `SpeechRecognition`，小程序只有
  WechatSI 插件，要真实 appid 绑定 + 后台申请，PC 端还识别不了。这条不问就会卡在第一期。
  用户选了第一期不做、降级为手动确认按钮。
- **顺序与判据** —— raw prompt 说了「前期先」，但没说前期到哪为止。
  真正的判据是「nono 在线上已有进度，切过去不能清零」，
  它把顺序钉死成：先逆出线上数据模型 → 再设计存档 → 才能画页面。
  这一条我是从 `什么算好` 第 2 条（不清零、不惩罚）反推出来的，不是 prompt 给的。

## improved prompt

下次提同类需求（把一个已上线的东西迁到另一个平台）可以直接用这个形状：

```text
把 <线上地址> 的功能迁移到 <目标平台>。

约束：线上已有真实用户数据，迁移不能清零 —— 迁移路径必须先确定，再动页面。
先给我一份「线上到底有什么」的清单（路由 / 数据模型 / 内容资产规模），
数字要从 bundle 里数出来，不要抄界面文案。

然后按依赖排出阶段，告诉我哪一步是关键路径、为什么。
不要一次做完，第一阶段只做关键路径那一层。

平台能力有差异的地方（<列出你已知的：语音、存储、路由>）单独列表，
每条给出「降级方案 + 是否第一期做」，我来拍板。
```

## 实际执行的形状

问清两件事之后，落地顺序是：

1. **P0 重定位** —— 重写 `vision.md`（宠物养成 → 成长陪伴工作台，五个域 + 家长端）、
   重写 `glossary.md`（7 → 19 个 Spec ID 区），清掉 README / app.json / package.json 里的旧描述。
2. **逆向核对** —— 不采信子 agent 的报告，自己用 python3 正则把每个承重数字重数一遍。
   这一步救回三处错误：贴纸 140 不是界面说的「约 200」、成就 11 不是 12、数学 6 阶段不是 5。
   也确认了两件影响规格的事：宠物刻度是 0–5 不是 0–100，线上**没有衰减机制**。
3. **P1 存档层** —— `doc.md`（25 条规格）→ `tasks.md` → 三个纯函数 + 三份测试 → `summary.md`。

## 这次 prompt 迭代学到的

**「逆向的结论要自己复核一遍」值得单独写进流程。** 子 agent 的报告里 3 个数字取自界面文案
而非代码，如果直接写进 `vision.md`，它们会以「已确认事实」的身份传播到后面每一份
`doc.md` —— 文档先行的项目里，一个错误的事实比一个错误的实现难清除得多。

**一个反例值得记住：** 我曾中途调 `SendMessage` 让子 agent 重发报告，
其实报告早已在上下文里。开始一轮工具调用前先确认「我要的东西是不是已经有了」。
