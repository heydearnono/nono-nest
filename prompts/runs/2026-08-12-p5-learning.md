## 这条 prompt 缺什么

**范围的默认值这次问对了，但漏问了一层：表现层的复用。** 两个表单页的 WXSS 有一套
相同的 `card` / `field` / `submit`。抽到 `app.wxss` 还是各写一份，是个没人拍板的选择，
我自己按「两处相同不算重复，三处才是」定了各写一份，并把理由写进
`english.wxss` 的头注释。prompt 里带上一句会更省：

> 样式重复到第三处再抽公共层，两处保持各自独立并在注释里说明。

**另一个缺口是「导出常量给页面用」的边界。** `doc.md` 起初只写了 `READ_OPTIONS`，
写英语页时才发现加减器也需要同一个上限 10，于是补了 `ENG_OPTIONS` 并回头改文档。
规律其实是普适的：**页面上任何一个「可选值」或「边界数字」都不该由页面自己写**，
否则就会出现「按钮按得出 11 而存档里落 10」。这条值得进 `AGENTS.md` 第 3 节，
下一轮如果再遇到第三例，就不该再靠临场发现。

## 复盘

**Prettier 第三次改写了我正在改的文档。** 这次学乖了：写完页面就先跑
`npm run format`，再跑 `npm run check`，一次全绿（6 份 doc.md，128 条规格，137 个测试）。
前两轮的复盘都写了这句，第三轮终于变成动作 —— 复盘生效需要的轮次比想象的多。

**唯一的测试失败是我的断言错了，不是代码错了。** `LEARN-10` 期望
`['checks', 'ledger', 'learning']`，实际是 `['checks', 'learning', 'ledger']` ——
`.sort()` 是字典序，`'learning' < 'ledger'`（第三个字符 `a` < `d`）。
**在断言里排序，就要按排序后的结果写期望**，凭「我写代码时的顺序」拼期望值是错的来源。

**26 条规格里最有价值的仍是那对「刻意不一致」的。** `READ-02`（书名必填）与
`ENG-06`（空表单也能打卡）单看每一条都像漏了校验，放在一起才是规则：
阅读的「读了哪本」除了这张表没有别处记，英语是跟着课程 App 上完课回来记一笔，
课程内容不由这张表定义。这已经是第三轮出现这类成对规格（`POINT-10`、`MOOD-03/04`）——
它们的作用不是发现 bug，是阻止下一个人把正确的行为改成一致的行为。

**`completeLearning` 里那个「先写记录再打卡」的顺序，是本轮唯一会静默出错的地方。**
顺序反了不会抛错、不会 lint 报警，只会让 `checks` 与 `ledger` 被旧的 `day` 覆盖掉，
表现为「打了卡但星星没涨」。写的时候意识到了，所以立刻加了 `LEARN-10`（三个兄弟键
同时在位）而不是只留一行注释 —— **能静默失败的顺序依赖必须有断言，注释挡不住重构。**
