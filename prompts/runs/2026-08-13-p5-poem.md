## 这一轮的三个判断

**`mastered` 是冗余字段，而这次冗余是对的。** `reward.js` 的 `poems_mastered` 判据读的是
存档上的 `mastered`，而依赖链是 `poem.js → pet.js → reward.js` —— 反过来 import 就成环。
所以「这首诗会背了没有」必须是**存档上直接读得出的事实**，不能是「知道古诗的档位表才算得
出来」的判断。代价是它与 `step === 5` 说同一件事、脏存档里可能对不上，处置是**读取路径
一律现算**（`poemsOf` 干脆只收 `step`/`due`/`wrong` 三个字段，`mastered` 进不来）、
写入方只有一个且每次同写两个字段。`ACHV-06` 补的那段断言是履约凭证：`reward.js` 一行没改，
`poem-10` 自己就亮了。**判断本身是「先看依赖方向，再决定数据形状」，不是反过来。**

**两个 feature 的档位表必须分家，而这件事只有一处能拦住。** 识字 `MASTERED_STEP` 是 7、
古诗是 5，`save.js` 的收敛函数是唯一同时看见两者的地方。混成一张表不会抛错、不会 lint
报警，只表现为「古诗 `step` 被夹到 7，于是永远算不到会背」—— 而那要熬 26 天才看得见。
所以 `SAVE-17` 的第一条断言是 `step: 99 → 5`，`save.js` 的上界拆成两个常量并在头注释
写下「两个 feature 的档位表不同」。glossary 里 `step` 仍只有一条定义：**共用的是词，
不是表。** `literacy/summary.md` 承诺过「`POEM` 只复用术语」，这就是兑现的形状。

**滑动窗口不是「另一种选法」，是一个会主动伤人的选法。** 线上
`floor(天序号/7)*3 % 109` 硬前进：缺席一周那三首要等约 36 周才回来，而且窗口不管孩子
学到哪 —— 启蒙阶段第 25 周就会撞上《登高》。顺序取未学的三首没有这两个问题，
分级由数据包顺序保证，选诗层不需要知道 `grade`（与识字「调度层不知道字频」同一条）。
`POEM-06`（上周只学了 `p1`，下周是 `p2`/`p3`/`p4`）是本轮最要紧的一条断言：
**少了它，下一个人「按线上抄回去」不会有任何东西报警。**

## 这条 prompt 缺什么

**它没说「落盘的与显示的必须是同一个序列」，而这是本轮唯一的新型不变式。** 「每周三首」
一旦落盘就多出一个水位，于是有了两条路径：`studyPoem` 写、`poemState` 在水位过期时当场
重算。两处都要「选三首」，两处都可以各写一遍规则 —— 那就是识字那轮 `queues` 事故的
同一形状，只是这次会晚一周才暴露（跨周才走到重算分支）。做法是抽 `pickWeekly(poems)`
一个函数、两处都调，`POEM-30` 断言两者的 id 序列相同。**规律：只要一个判据有两个调用
时机（写入时、读取时），就得先问「共用的是函数还是文字」。**

**它没说清「已会背的诗要不要留在本周三首里」。** `doc.md` 有 `POEM-04`（学过的仍留着）
和 `POEM-10`（会背的不进任何列表），两行分开看都成立，合起来才有一个空隙：**一周内连着
五天表态、当周就熬到会背的那首**。我在写测试前自己发现并补了过滤，但这与上一轮
`LITERACY-04` / 设计段那次矛盾是同一类 —— 规格表里两行引用同一个状态时，得代进同一个
例子算一遍。上一轮的教训写成了「规格之间要交叉验算」，这一轮说明那条还没被执行到位：
**交叉验算要枚举到边界情形（这里是「一周内走完全程」），不只是典型情形。**

**数据包的订正取舍不在 prompt 里，是本轮现拍的。** `p68 题西林壁` 标 `dynasty: '唐'`
（苏轼是宋人），而识字那轮对 1107 条空例句的处置是「照搬不修」。分界拍成**缺内容还是
错内容**：空例句缺了页面不显示；「唐 · 苏轼」会被显示出来且无争议错，改一个字段不需要
第二份数据源。同一条数据包里另外两处重复正文与 12 条念不出「X 代」的朝代**没改** ——
后者靠页面显示 `{dynasty} · {author}` 而不是线上的 `${dynasty}代${author}` 化解。
**取舍写进了数据包头注释与 `doc.md`，因为下一个人一定会问「为什么只改这一处」。**

## 复盘

**第一次一个测试也没红。** 五批增量（6 → 11 → 17 → 22 → 32）加存储层两条、门禁全绿，
全部首跑通过。不是因为这轮简单，而是因为 `literacy.js` 是逐字可参照的模板：
`poem.js` 的私有 helper、宽容/严格分界、发放先行记录后写、对象同一性，全都是同构的第二遍。
**代价是这一轮几乎没学到新东西 —— 值得记的判断都在上面那三条设计上，不在实现里。**

**存储层先行第四次生效。** `save.js` / `importOnline.js` 与它们的规格先落地，
所以 `poem.js` 里除了 `poemsOf` 那一次常数代价的重夹之外，没有任何防御性收敛。
这条已经固化在 `tasks.md` 的排序里（第 1 节永远是存储层），不再需要复盘。
