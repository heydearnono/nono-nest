## 这一轮的四个判断

**一条恒真的规格看起来与一条真规格完全一样。** `IMPORT-04` 从 P1 起断言
`expect(result.days['2026-08-10']).toEqual(aug10)` —— 它测的是「整份透传确实原样搬」，
永远绿，而它掩盖的事实是：搬进存档的是线上形状，本仓库任何读取点都读不出来
（`checks` 这个键根本不存在，线上叫 `completedTasks`）。**规律：断言「A 原样等于 A」的
规格没有信息量，它只能证明搬运没出错，不能证明搬过来的东西有人认得 ——
凡是「透传」的字段，规格必须配一条「读取入口能从它读出什么」。**
本轮之后这类规格在 `importOnline.js` 上是 `0` 条。

**fixture 的形状比 fixture 的内容重要，而错的形状会静默通过所有断言。**
`ONLINE_EXPORT` 里 `completedTasks: { wake: true }` 是个布尔，真实线上形状是
`{ wake: { completed: true, completedAt: '2026-…' } }`。布尔那份 fixture
**既测不出墓碑**（`completed: false` 的元素不该写键）**也测不出 ISO 转毫秒** ——
两条本轮最核心的映射规则在它上面都是无操作。改 fixture 是本轮工作量最不显眼、
最容易漏的一件事，而它一改，`IMPORT-01` / `IMPORT-04` 两条既有断言跟着要改。
**规律：逆向来的 fixture 要按 `path:offset` 核一遍形状，不能按「测试需要什么」造 ——
简化过的 fixture 会把它简化掉的那部分逻辑一起变成不可测。**

**「不知道」不能显示成 0，而这一条的处置往往不在数据上。** 缺陷 13 的成因是
「今天启用中的任务数」被当成每一天的分母。本仓库的分母**同样只能是今天那个数** ——
存档里没有「上周三有哪些任务启用着」这笔数据，而那不是遗漏：
要记就得给每次启用/停用落一条时间戳，那是一份新的水位、一个新的收敛点、
一段新的导入映射。所以处置在显示上（`hasRecord` 为 `false` 的格子显示「—」且点不动），
不在分母上。**规律：一个近似值不一定要修成精确值，但它必须在界面上被标成近似 ——
把近似值显示成确定值，是让家长按一个假数字做决定。**

**一个状态有两种来历时，文案只能说两边都成立的那件事。** `'cancelled'` 的两个来源：
家长驳回（退了勋章）、`IMPORT-12` 映射来的线上 `rejected`（**从来没被扣过勋章** ——
线上批准时才扣，所以无款可退）。写「已退回」对第二种是谎，写「已驳回」对第一种
漏掉了退款这件事。选「已取消」。**规律：给一个枚举加取值时要数清它有几个产生点，
每个产生点的语义差异都会挤进那一个显示文案里。**

## 这条 prompt 缺什么

**它没说「拆文件的判据」需要在文件粒度上重新问一遍。** 第二段定下的是
「拆页面看只读性」，本轮同一条判据在 utils 上又用了一次：`boardState` / `dailyReport`
与 `resolveRedemption` 三个函数都碰 `days` 与 `redemptions`，按「碰哪个字段」
它们该在一个模块里；按「它写不写盘」，前两个新开一个文件。选后者。
代价是 `parentTasks.js` 从此名不副实（它其实是「家长域的写入口」），**不改名** ——
改名要动两处 import、一个测试文件与三份 `doc.md`，换来的只是一个更准的词。
**规律：同一条判据在页面粒度与文件粒度上都适用，而「代价是一个名字变得不准」
通常比「代价是一次跨三份文档的改名」便宜 —— 把这笔债写下来就够了。**

**它没提「一次映射改动会不会动到别的域的数字」。** `daysFromOnline` 落地之后，
`utils/reward.js` 的 `JUDGES` 里恰好四条读 `days` 内部的判据
（`reading_days` / `veggie_week` / `room_tidy` / `daily_all_done`）第一次能在
导入来的存档上数出数字 —— 在此之前它们对导入的存档**一条都数不出来**。
所以这是一次**有后果的映射**，不是补一段搬运代码。处置是 `IMPORT-19` 专门断言这件事，
并在 `doc.md` 里点名那四条。**规律：改一个「透传变映射」的字段之前，
grep 一遍谁读它的内部结构 —— 那些读取点的输出会在这一轮静默改变。**

**它没说「页面层的坑要不要写进 summary」。** 本轮踩到两个小程序特有的：
嵌套 `wx:for` 的 `index` 被内层遮住（柱子是三条趋势 × 七天，而每根柱子下面
要按下标去 `week.days` 取星期几）；布尔穿过 `dataset` 之后不该判 `=== true`
（模板序列化过一次）。两个都在跑门禁之前自己看住了。写进 summary 了，
因为它们是**平台知识**而不是本轮的设计 —— 下一个页面还会遇到。
