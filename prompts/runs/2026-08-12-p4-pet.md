## 这一轮的三个判断

**该不该加线上没有的规则 —— 这个不自己拍。** 逆向确认线上 `satiety` 只升不降
（`lastFedAt` / `lastPlayed` / `decay` 在 714KB bundle 里 0 次出现）之后，
问题不是「怎么实现衰减」而是「要不要偏离迁移目标」。加衰减会改存档结构、
会让宠物可能处于「更差」的状态，直接碰「温和，不惩罚」这条产品原则。
所以停下来让人选，而不是像 P3-a 那样自己拆段。**上一轮的复盘正好写了这句改进建议
（「如果下一阶段的前置条件还没就绪，先说明依赖关系并给出拆分方案，不要直接开工」），
这轮它生效了** —— 留档的复盘不是写给自己看的仪式，是下一轮的输入。

**衰减的边界条件先写成规格，再写实现。** `settleFullness` 有三个容易写错的点：
`lastFedAt` 该前进多少、`lastFedAt === 0` 怎么办、时钟回拨怎么办。
三个都先落成 `FULLNESS-01` / `04` / `06`，实现时它们收敛成两个 `if`
（`steps <= 0` 一支同时吃下不足一步、回拨、幂等三种情况）。
**规格数多于分支数是好现象**：说明分支是推出来的，不是防御性地堆出来的。

**「打卡走 `pet.js`、取消走 `point.js`」的不对称是有意保留的。** 写页面时手很想加一个
`uncheckAndShrink` 让两边对称，但那等于「取消打卡要扣经验」—— 与线上一致的做法是
什么都不动。用 `MOOD-06` 把「不回退」钉住，让不对称有一条断言撑着，
而不是靠首页那段 JSDoc 的说服力。

## 这条 prompt 缺什么

一个字的 prompt 能跑完一个阶段，靠的仍是仓库里的阶段表、宪法与门禁。
这轮暴露的新缺口是**范围的默认值**：「做宠物」既可以是「纯函数 + 宠物页」，
也可以顺手把首页宠物卡片、宠物动画、粒子特效都做掉（线上都有）。
我用 AskUserQuestion 问了，但更省一轮的写法是 prompt 里带上：

> 只做能被规格钉住的部分，表现层的加法（动画、特效、第二个入口）单独开一轮。

## 复盘

**Prettier 又改写了我正在改的文档。** 与上一轮同一个坑：`doc.md` 里的表格列宽被重排，
第一次 `npm run check` 挂在 `format:check`。写完 markdown 表格就跑 `npm run format`，
别等门禁告诉我 —— 这条已经犯了两次，值得当成肌肉记忆。

**两次编辑失误都出在 markdown 表格上：** 一次是猜了表格的空格填充导致 Edit 匹配不上，
一次是少了个换行把 `PET-09` 和 `PET-10` 合成了一行。表格行的边界在视觉上不明显，
改之前先把那一段读出来照抄，比凭记忆拼便宜。

**33 条规格里最有价值的是那两条「刻意不一致」的。** `MOOD-03`（陪玩时开心已满，
经验也不涨）与 `MOOD-04`（打卡时开心已满，经验照涨）单看每一条都像写错了，
放在一起才是规则。这类断言的作用不是发现 bug，是**阻止下一个人把正确的行为改成一致的行为**
—— 与 P3-a 的 `POINT-10`（流水与货币刻意对不上）是同一类。
