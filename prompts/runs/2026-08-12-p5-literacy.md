## 这一轮的三个判断

**逆向读出来的不是「线上怎么做」，而是「线上哪里坏了」。** 这一轮把线上 bundle 的识字
调度逐行读完，读出三个 bug 与一个死角：一个字能同时在 `masteredChars` 与错误列表里、
`learnedChars` 只写不读、错误数有两处减、2000 字学完后新字池空导致这一格**永远打不了卡**。
把它们当规格抄过来是最省事的读法，但那会把 nono 的复习队列继续锁在「每天都是同一批新字」。
所以本轮的做法是：**五个平行结构压成一条 `chars[字] = { step, due, wrong }`**，
让那三个 bug 不是被防住而是**表达不出来**；死角补一条改判（`LITERACY-26`）。
「线上是唯一的需求来源」与「线上的行为都是需求」是两句不同的话。

**六个到期日 → 一个 `due` 加一个 `step`。** 线上一次评分把 1/2/4/7/14/30 全写成六个日期，
判定是 `some(d <= 今天)` —— 最早那个永远说话，于是六档间隔的**实际效果恒为 1 天**。
这不是抄漏了一行，是数据结构允许了一个不该存在的状态（「同时在六个档位到期」）。
`LITERACY-05` 因此写成逐档前进的断言：每次评分都发生在上一次的 `due` 那天，
一路钉住 +1 / +2 / +4 / +7 / +14 / +30。**这条测试的作用是让「照线上改回去」这件事失败。**

**队列的取法只能有一份。** 打卡改判要问「还有没有新字、到期的字复习完没有」，
问的必须与页面看到的是同一套判据。第一版 `gradeChar` 靠回调 `literacyState` 去问，
结果那时 `days` 里还是评分**前**的记录 —— 刚评的字没被排除，「没什么可做了」这一支
永远走不到，`LITERACY-26` 直接红。抽出 `queues(chars, key, graded, now)` 之后两处
传的都是评分**后**的输入。**共用判据要共用的是函数，不是「调用另一个入口」。**

## 这条 prompt 缺什么

**`doc.md` 自相矛盾，而两行分开看都成立。** 设计段写
`due = dayKeyAfter(now, REVIEW_STEPS[新 step])`，`LITERACY-04` 写「第一次答对 `due` 是明天」——
按下标算第一次答对会等 2 天。两句话各自读都对，**只有把它们放进同一个断言才会打起来**，
所以它是写测试时才暴露的，不是评审能看出来的。按第 5 节第 2 条先改文档：
`step` 从「间隔表的下标」改成「连续答对的次数」（`0`~`7`），`0` 于是空出来专门表示
「上次答错、今天重来」，不必再加一个字段区分它与刚学的字。
`glossary.md`、`storage/doc.md`、`save.js` 的 `STEP_MAX`、`importOnline.js` 一起动。

规律：**规格表里的两行如果引用同一个变量，得当场把它们代进同一个例子算一遍。**
第五轮的教训是「规格要指明断言哪一层」，这一轮是「规格之间也要交叉验算」——
都属于「规格表本身可以不自洽，而门禁只查 ID 有没有对应测试，查不出语义冲突」。

**门禁会去 lint 别人的产物，这件事 prompt 与 doc 都没有涉及。** `.scratch/` 在 `.gitignore` 里，
但 ESLint 扁平配置不再自动跳过点目录、Prettier 也不看 `.gitignore`，
于是 `npm run check` 对着三个 minified bundle 报了 531 条 `no-undef`。
本轮顺手加了两行忽略。它不属于识字域，但**它挡着门禁，而门禁是本仓库唯一的一致性保证**——
下一轮无论做什么都会先撞上它。

## 复盘

**「先 format 再 check」第三次生效，仍然一次全绿。** 这条动作已经固化在 tasks.md 收尾节，
不再需要复盘。

**测试失败两次，一次是断言写错，一次是代码写错 —— 这是前六轮里第一次有真的代码错误。**
断言那次仍是老毛病：`Object.keys(day).sort()` 给的是 `['checks','learning','ledger']`
（ASCII 里 `'learning' < 'ledger'`），我按语义顺序写了期望。第五、第六轮的结论
（「期望值要从契约推，不要从直觉抄」）第三次被同一个 `.sort()` 验证。
代码错误那次是上面 `queues` 那条，性质不同：**它是「两处必须问同一个问题」被写成了
「一处调用另一处」**，而那个调用带着一个过期的入参。

**能静默失败的地方必须有断言 —— 第五次。** 前四次分别是顺序依赖、字典序、边界数字、
周日的 `getDay() === 0`，这一轮是 `REVIEW_STEPS` 的下标差一位：
错一位不抛错、不 lint 报警，只表现为「第一次答对等两天」，而这件事**要等到第二天才看得见**，
在真实使用里几乎不可能被发现。所以 `LITERACY-05` 不是「测一下间隔对不对」，
它是这个仓库里唯一能看见这个错的东西。

**点亮一格灰格子会打翻另一个域的规格。** `learningModules.js` 里填上 `page` 之后
`LEARN-02`（「只有阅读与英语 `ready`」）当场变成假。这是第一次出现
**跨域的规格因为本域的进展而失效**，改法照第 2 条：先改 `learning/doc.md` 的那一行与状态行，
再改测试。中途还写歪过一版 —— 把它含糊成「已做完的模块 `ready` 为 `true`」，
那等于让规格跟着实现走。规格表要点名期望值，哪怕下一轮又得改一次。
