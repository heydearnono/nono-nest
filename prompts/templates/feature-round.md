# 模板：一轮功能落地的 prompt 记录

> 从 `runs/` 里 12 份同骨架的记录提炼（`p3a-point` 起到 `p7-parent-3` 止，
> 2026-08-12 ~ 08-17）。`AGENTS.md` 第 6 节说「同一类 prompt 用过两次以上提炼成模板」，
> 这一份逾期很久 —— 12 次之后才落，所以它记的不是设想，是实际稳定下来的形状。
>
> **用法**：复制到 `runs/YYYY-MM-DD-<topic>.md`，照着填。
> 方括号是待替换的占位符，引言块是写作要求、填完删掉。

## 这份骨架为什么是这四段

12 份记录都收敛到同样的四段，不是约定出来的，是每段各自挡住了一类事后无法补救的丢失：

| 段                 | 挡住的丢失                                                    |
| ------------------ | ------------------------------------------------------------- |
| 原始 prompt        | 「当时到底说了多少」—— 事后一定会记成比实际说得更清楚         |
| 这一轮的 N 个判断  | 「为什么这样而不那样」—— 代码只留下结果，候选项与代价不留痕   |
| 这条 prompt 缺什么 | 「谁替人做了决定」—— 这些位置下一轮换个人会做出不同选择       |
| 复盘               | 「哪里差点出事」—— 红灯会留在 CI 里，跑之前自己看住的不会留下 |

前两段是事实与判断，后两段是这套记录唯一会反过来改变下一轮行为的部分。

---

# [YYYY-MM-DD] · [阶段编号，如 P7 第三段] · [一句话主题]

- 阶段：`docs/vision.md` [阶段]（[SPEC 区名]）——[**这一轮之后什么变了**，一句话]
- 产出：[逐个文件列出，新增标「新增」，改动写清改了哪一部分]

> 「产出」不是 `git diff --stat` 的复述：它要能让人只读这一行就知道
> **改动落在哪几层**（`data/` / `utils/` / `pages/` / `tests/` / `docs/`）。
> 层次缺一块通常是信号 —— 比如动了 `utils/` 却没动 `docs/`，就是文档先行没走。

## 原始 prompt

```
[原样粘贴，不美化、不补主语。如果它就是「继续」两个字，就写「继续」]
```

（[**上下文交代**：这一轮的设计口子是在哪一轮被指名的、指在哪份文档的哪一节；
如果有当场拍板的选择题，把选项与人选了哪个写下来；
跨了几次上下文压缩、中途有没有新的人类输入；从上一轮延续的安全约束。]）

> 保留 raw prompt 是这套记录唯一的价值来源（`prompts/README.md`）。
> **「继续」这种极短 prompt 不是记录的失败，是它最该记的一类**：
> 它证明信息不在这句话里，而在文档里 —— 括号里那段交代就是在指认它到底在哪。
> 若括号填不出来，说明上一轮的收尾没把口子写进文档，那本身是要在复盘里记的事。

## 这一轮的 [N] 个判断

> 一轮通常是三到四个。**只写有过候选项的**：没得选的事不是判断，是执行。
> 每条的形状固定为三层 —— 加粗一句结论开头、中间写候选项与各自的代价、
> 末尾一句 `**规律：……**` 抽出可迁移的那部分。
> 规律那句是给下一轮的自己看的，所以**不许出现本轮的专有名词**：
> 写「派生值当持久化的键要问算法会不会变」，不写「贴纸 id 别用下标算」。

**[加粗的结论句，本身要能独立成立]**
[候选项各是什么、代价的形状差在哪、为什么选了这个。
写代价而不写优点 —— 优点是选它的理由，代价才是下一轮推翻它时要衡量的东西。]
**规律：[脱掉专有名词的可迁移判据]**

**[第二个判断]**
[……]
**规律：[……]**

## 这条 prompt 缺什么

> 这一段是**替人做了决定的清单**，不是抱怨 prompt 太短。
> 每一条的判据是：这个位置若换一个 AI 接手，会不会做出不同的选择？会，就写下来。
> 同样以 `**规律：**` 收尾。
>
> 反复出现的三类，可以拿来对照自查：
>
> 1. **脏数据在哪一层处理掉** —— 收敛层丢掉，还是每个读取点各判一次
> 2. **认不出的值留还是删** —— 「留着但不读」这类处置要两层各一条规格，
>    一条证明留了、一条证明没读；只写一条的话两种相反实现都能全绿
> 3. **界面拆不拆** —— 判据是两块界面共用多少数据，不是行数

**[它没说 ……]**
[两个方向各对一半在哪、选了哪个、于是省下了什么或欠下了什么。]
**规律：[……]**

## 复盘

> 至少覆盖四件。前两件是事实，后两件才会改变下一轮的行为。
>
> 1. **门禁结果**：`npm run check` 几次红灯、红在哪；跑之前自己看住的自伤也要写
>    —— 那些不会留在 CI 里，不写就等于没发生
> 2. **规格里最值得留的那一对**：说清少了其中一条，哪种错误实现能全绿
> 3. **流程纪律有没有守住**：小步勾选、文档先行、范围外不越界。
>    没守住就写下来，记它不是自责 —— 是因为那条纪律本来在保护某个可观测的东西，
>    要写清丢的是什么（例：批量打的勾，事后无法区分哪条先做完）
> 4. **留给下一轮的缺口**：哪些是在等某一轮，哪些是永久不做，
>    哪些卡在代码之外（账号、插件、真机）

**[门禁：几次红灯 / 零红灯，以及跑之前看住的自伤]**
[……（418 条规格、17 个测试文件这类数字写实际值）]

**[本轮最值得留的一对规格]**
[少了后者，什么样的错误实现会全绿。]

**[流程纪律]**
[守住了就一句话，没守住写清丢了什么、下一轮怎么办。]

**[留给下一轮的]**
[……]
