# 产品愿景

> 这份文件记录 AI **无法从代码推断**的东西：为什么做、给谁做、什么算好、什么明确不做。
> 曾用 `待确认` 标记 AI 起草的假设，需要人确认后摘除；**六条到 2026-08-18 已全部摘除**
> （见「设计假设」一节）。新增假设时沿用这个标记。

## 是什么

给 nono（5 岁）的**成长陪伴工作台**微信小程序。一个入口下有五件事：

- **学习** —— 识字、古诗、数学、阅读、英语，各自有自己的进度与复习节奏
- **自律** —— 每日习惯打卡（起床、刷牙、穿衣、整理……）
- **健康** —— 饮食、喝水、运动、排便、洗澡的记录
- **奖励** —— 打卡产出积分，积分换贴纸、换勋章、换现实中的小特权
- **宠物** —— 一只随互动变化的小伙伴，是上面四件事的情绪出口

外加一个**家长端**：任务管理、积分规则、每日报告、设置，用 4 位 PIN 长按进入。

宠物是其中一个模块，不是整个产品。这一点与本仓库早期版本不同 —— 早期定位是纯宠物养成，
2026-08-11 随线上工作台的功能迁移改为现在的定位。

## 前身：线上工作台

本项目的功能来源是已上线的 PWA <https://xiaoluzhu.net/>（「Nono 工作台」，
manifest 里的自述是「5岁女孩成长陪伴工作台」）。它是 Vite + React 单页应用，
数据存在浏览器 IndexedDB（库名 `nono-workbench`），无后端。

小程序版是**功能迁移**，不是重写产品。判断某个行为该怎么设计时，线上实现是第一参考；
偏离线上行为必须在对应 `doc.md` 里写明理由。

线上已有的内容资产（迁移时直接沿用，不重新收集）：

| 资产   | 规模    | 来源                     |
| ------ | ------- | ------------------------ |
| 汉字库 | 2000 个 | 线上 `characters` 数据包 |
| 古诗库 | 169 首  | 线上 `poems` 数据包      |
| 贴纸   | 140 个  | 线上 bundle 内常量       |
| 成就   | 11 个   | 线上 bundle 内常量       |

规模数字是从线上 bundle 里逐条数出来的，不是界面文案。界面上说的「约 200 个贴纸」
与实际的 140 个不符，以本表为准（依据见 `docs/features/storage/doc.md`）。

## 给谁做

**两类使用者，界面与目标都不同：**

- **nono（5 岁）** —— 主要使用者。不识全字、注意力短、需要即时正反馈。
  界面必须能在「不读长句」的前提下用：大按钮、emoji、颜色区分。
- **家长** —— 配置者与旁观者。关心趋势和报告，不关心动画。
  家长端藏在 PIN 后面，孩子不应该误入。

单一家庭自用。不做多人、不做社交、不做排行榜、不做分享传播。
因此：无账号体系、无后端、无云开发，所有数据存在本机 storage。

## 什么算好

按重要性排序，冲突时上位覆盖下位：

1. **每天想打开一次。** 驱动力是「我的进度在长」和「小伙伴在等我」，不是签到奖励本身。
2. **温和，不惩罚。** 漏一天不清零、不倒扣、不断连击提示羞辱。
   宠物会不开心，但**不会死、不会消失、不会清零进度**。长期不打开只会睡着，回来能恢复。
3. **孩子能独立完成一次互动。** 不需要家长在旁边读屏。
4. **一次互动短。** 单个打卡 10 秒内结束；一次学习不超过 5~10 分钟。
5. **状态可解释。** 为什么涨了积分、宠物为什么不开心，界面上要能看懂，不能只给数字。
6. **家长的配置不该被孩子的操作破坏。** 规则、PIN、任务清单只在家长端可改。

## 明确不做

- **不做真钱内购。** 星光 / 宝石 / 宠物粮 / 勋章是行为记账单位，只能靠打卡产出，
  不能购买、不能充值。这与早期版本「不做货币」的措辞不同：货币做，付费不做。
- **不做付费抽卡。** 贴纸抽取只消耗打卡赚来的勋章，且每日有免费次数上限。
- 不做倒计时催促、推送轰炸、连击断裂的负面提示
- 不做死亡 / 跑掉 / 送走等负面终局
- 不做联网请求（含埋点、崩溃上报、远程配置、内容更新）
- 不做多孩子档位（存档单例，见「设计假设」）
- 不上架发布，不申请小游戏类目（个人号无法选择）

P1 是关键路径：所有页面都读写同一份存档，结构定错了后面全要改。

P1 只做了**纯函数那一层**（`dayKey` / `save` / `importOnline`）。真正调
`wx.setStorageSync` 的读写包装留给 P2 的首页，粘贴 JSON 的导入界面留给 P7 的家长端 ——
这两件都需要一个页面才有意义。另外 P1 的存档只接线上 19 个顶层键里的 10 个，
积分规则、学习进度、贴纸收藏要等 P3 / P5 定完结构才能进存档，
**所以线上导出的 JSON 原文要留着，届时需要再导入一次**（细节见
`docs/features/storage/summary.md`）。

P2 落地后首页可以打卡了，但**打卡不发放任何积分** —— `starReward` / `petFoodReward`
两个字段已经在存档里躺着，等 P3 来读。这是刻意的：先给孩子看到星星、再在 P3 调整发放
规则，改动就变成了「扣星星」。所以 P2 的首页是「有反馈但不涨数字」的过渡态
（细节见 `docs/features/habit/summary.md`）。

P3 拆成两段，**两段都已完成**。P3-a（`POINT`）：打卡发星光与宠物粮、取消扣回、
当天流水，首页顶部有了货币带。当时**勋章恒为 0** —— 它只有两个产出点（今日全勤、
成就解锁），而今日全勤要核心 id 全打满，其中 `literacy` / `reading` 要 P5 的学习页、
`exercise` 等要 P6 的健康页才可能被打上。所以 P3-b 的顺序依赖 P5 / P6，
不是纯粹的「下一步」（细节见 `docs/features/point/summary.md`）。P5 首段补上了
`reading`，P6 补上了 `exercise` / `vegetables` / `poop` / `bath`，P5 识字那一轮补上了
最后一条 `literacy`，核心 id 于是全都有了打卡入口。

**P3-b（`REWARD` / `ACHV`）已完成**：今日全勤 +1🏅、周奖励 +5⭐+1💎、十一条成就、
三张兑换卡，勋章与宝石都不再恒为 0，「打卡 → 星光 → 勋章 → 兑换」这条链第一次闭合。
**全勤名单从线上的 8 条收敛成 7 条：去掉 `bath`** —— 它是唯一的周任务
（`weeklyTarget: 3`），要求「一周洗三次」的任务每天打满与它自己的定义矛盾，
于是线上的今日全勤在不洗澡的日子结构性不可能达成。名单落在任务元素的 `core` 字段上，
不落在 `utils/` 的平行数组里（家长删掉一条核心任务后，平行数组会让全勤永久不可达）。
兑换也偏离了线上：**申请那一刻就扣勋章**，记录停在「待家长兑现」——
线上批准时才扣，中间勋章被花掉那条申请就永远批不了
（细节见 `docs/features/reward/summary.md`）。

**P4 主动加了一条线上没有的规则：饱腹度随时间衰减，每 6 小时 -1，下限 0。**
线上的饱腹度只升不降，连点几次喂食就永久饱着，宠物粮失去用途，
「小伙伴在等我」（「什么算好」第 1 条）也就无从成立。这是 2026-08-12 的人拍板决定，
不是逆向所得，所以记在这里而不是当成迁移细节。

**只衰减饱腹度，开心度不衰减。**「饿了要喂」是照顾，孩子能立刻解决（打卡赚粮 → 喂食）；
「你不陪我我就难过」是情绪绑架，与「温和，不惩罚」冲突，而且昨天没陪也补不上。
衰减到 0 的唯一表现是界面上的「饿饿」角标 —— 不掉等级、不掉经验、不清零进度，
符合「什么算好」第 2 条与「明确不做」的负面终局条款。
存档因此新增 `pet.lastFedAt`（`SAVE-12` / `IMPORT-10`），结算发生在宠物页的 `onShow`
（细节见 `docs/features/pet/summary.md`）。

**P5 拆成四段：首段（2026-08-12）做阅读与英语（`READ` / `ENG`），第二段做识字
（`LITERACY`），第三段做古诗（`POEM`），第四段做数学（`MATH`）—— 四段都已完成。**
阅读与英语在线上几乎没有学习逻辑 ——
填一张表、点一下完成，就是一次打卡，正适合先把「学习域怎么接进
已有的打卡 → 发放 → 成长这条链」验证一遍。
tabBar 因此多了第三个 tab（`📚 学习`），入口页列五格，未做的格子是灰的
（细节见 `docs/features/learning/summary.md`）。

顺带把 P3-b 的一个缺口填了：`reading` 是今日全勤的核心 id 之一，现在它有打卡入口了。

**识字（第二段）已完成**：2000 字搬进 `data/characters.js`（顺序一字不动，
前 415 条字频序、其后拼音序），复习调度**没有照搬线上** —— 线上一次评分写六个到期日、
判定取最早那个，实际间隔恒为 1 天，学过的字每天都回到队列，第 20 个字之后老字再也轮不到。
本仓库一个字存一条 `{ step, due, wrong }`，`1/2/4/7/14/30` 六档真的当间隔用，
七次答对（跨 58 天）才算掌握（细节见 `docs/features/literacy/summary.md`）。
古诗**不复用这套调度**：线上古诗按周轮换 3 首、没有错误计数，两条路径本来就是分开的，
`glossary.md` 里那句「共用同一套调度」已改成「共用同一套术语」。

**古诗（第三段，2026-08-13）已完成**：169 首搬进 `data/poems.js`（顺序一条不动，
只订正 `p68 题西林壁` 的朝代 `唐 → 宋`），每周三首 + 会背判定 + 国学打卡一轮做完。
**三处偏离线上**，都不是口味问题：

1. **本周三首按未学顺序取并落盘**，不是 `floor(天序号/7)*3 % 109` 的滑动窗口 ——
   那个窗口硬前进，缺席一周那三首要等约 8 个月才回来，还会让启蒙阶段的孩子
   第 25 周撞上《登高》；而且它的周界落在周四（纪元是周四），与全仓其余地方的
   「本周」不是同一个口径。
2. **间隔表 `1/3/7/15` 真的当间隔用**，五次表态、跨 26 天才算会背。线上一次写六个
   到期日、判定取最早那个，而且那份调度是 `||=` 写的，**只在首次学习时写过一次**，
   于是一首诗从第二天起永远到期。同时加了线上没有的「😅 还没背下来」入口，
   **它照样打卡照样发星光** —— 线上两个按钮发一样的东西、其中一个还白送一首进
   「已会背」，谎报严格占优。
3. **拓展那 60 首有一条走得通的路**（109 首必背全部会背后解锁）。线上是选诗池过滤
   加目录行不可点两道墙，那 60 首永久不可达，页头「拓展 0/60」是个永远的 0。

`ACHV` 区的 `poem-10` 成就因此自己就亮了，`utils/reward.js` 一行没改
（细节见 `docs/features/poem/summary.md`）。

**数学（第四段，2026-08-14）已完成，P5 至此完整 —— 入口页五格全亮。**
30 道固定题 + 六阶段 + Boss 通关一轮做完，题库一字未改（连 `p68` 那样的订正都没有：
`m2-2` 看着像错，实际是线上的判定错了，判定统一走 `answer` 之后自然消失）。
**四处偏离线上**：

1. **出题优先没答对过的题**，不是 `天序号 % 4` 的循环 —— 那个循环与答对过什么无关，
   已经会的题一直重复、不会的题永远轮不上。
2. **打卡条件是当天三道题都答过，答错也算**，不是线上「答对才计入」加一个
   刷不完的 `gamesCompleted`。
3. **升阶要本阶段 5 道（含 Boss）都答对过一次**，不是「6 局对 4 局」那个可以刷同两道题
   的计数器。Boss 算在 5 道里，否则升阶只要 4 道普通题，而 Boss 是当天必出的第三道。
4. **选项按 `dayKey` 确定性打乱** —— 线上选项是常量，而 30 道里 20 道 `answer: 1`
   （阶段 4、5 的十道全是），「永远点第二个」是必胜策略。

**数学不做复习调度**：没有 `step` / `due`、没有第三份间隔表，30 道题一共只有 30 道，
「明天再见」由出题顺序自然完成。顺带修掉 `utils/reward.js` 里一行判据：`math_games`
读的字段名（`games`）线上本仓库两边都不存在，而「进度恒 0」既是「子键还没有」
也是「字段名写错」的表现，两者观测结果一样 —— 教训是**空进度的断言必须配一条非空的**
（细节见 `docs/features/math/summary.md`）。

**P6（健康）一轮做完，没有第二段。** 四条健康任务在 P2 就已落库，本轮只补了读写它们的那一层
（`utils/health.js` 三个函数 + 一个页面），没有新的数据包、没有新的经验常量
（健康打卡与自律打卡同价，都是 5 点经验）。tabBar 因此有了第四个 tab（`🥗 健康`）——
线上健康是从首页跳进去的普通页面，本仓库把它提成 tab：学习已经是 tab 了，
两件同为「每天要进去一次」的事放在两个层级上，5 岁的孩子要记两套路径
（细节见 `docs/features/health/summary.md`）。

P6 唯一的新原语是 `weekKeys`（`utils/dayKey.js`，`DAY-06` ~ `DAY-09`）：洗澡卡要显示
「本周 N/3」。它同时是 P3-b 周奖励要用的那份键，所以落在 `DAY` 区而不是健康域里。
**`bath` 的 `weeklyTarget: 3` 只做显示、不做门禁** —— 做成「一周只发 3 次」会引出
「第 4 次洗澡要不要给星星」这种要拍板的问题，而它与「温和，不惩罚」的方向相反。

**P7 拆三段，三段都已完成（第一二段 2026-08-14，第三段 2026-08-17）。**
第一段 = 长按入口 + PIN 验证 + 家长设置 + 导出/导入/清空；
第二段 = 任务管理（启用、编辑、新增、排序）+ 兑换卡启用；第三段 = 看板 + 每日报告 + 兑换审批。
这么切是因为**数据搬迁不能再等**：`utils/importOnline.js` 从 P1 起就能把线上 JSON
映射成本仓库存档（15 条规格全绿），**但全仓零调用点** —— nono 线上已有的进度至今
搬不过来，而第二段要改的 `habits`、第三段要读的 `days` 都应该先是真实的那一份。
`pages/parent/parent.js` 是**全仓第一个 `importOnlineSave` 调用点**，
连着三轮 summary 记的「最大的一个缺口」到此封上。

**三处偏离线上**：PIN 输错**连错 5 次冷却 60 秒**（线上无限次重试，而 4 位数字只有
一万种组合）；导入换成**粘贴框 + 摘要确认弹窗**，两种失败给两句不同的话
（线上是 `prompt` 粘贴、静默整份覆盖、`JSON.parse` 抛错时一个 unhandled rejection）；
长按从 3 秒缩到 **1.5 秒**且换成一次 `setTimeout`（线上 100ms 轮询，清理只挂在一半的
抬手路径上，滚动接管时蒙层会在三秒后自己弹出来）。

顺带把线上的两个缺陷从结构上关掉：**改 PIN 只剩一个入口**（`saveSettings`，
非 4 位数字抛 `RangeError`；线上规则页那个边打边写存档，删到一位就落盘），
**`dailyGoal` 的上界挪进 `normalizeSave`**（线上那道 `Math.min(12, …)` 在设置页里，
导入一份 `dailyGoal: 99` 绕得过去，看板会永远显示「差 99 项」）。
存档因此多两个字段 `parent.pinFails` / `parent.pinLockedUntil`（`SAVE-19` / `IMPORT-16`）——
它们是**水位不是设置项**，线上没有，导入落 `0`
（细节见 `docs/features/parent/summary.md`）。

**第二段（2026-08-14）让家长端从「只能看」变成「能改」**：18 条任务的启用、编辑
（名字 / 图标 / 两个产出值 / 是否计入今日全勤）、新增、上移下移，加三条兑换卡的启用停用
（`PARENT-24` ~ `53`）。这一轮**存储层不是顺带产出而是前置条件**：`habits` 的元素收敛
（`SAVE-20` ~ `22`）与线上 `tasks` 的逐元素映射（`IMPORT-17`）不做完，家长端改的就是
一个本仓库认不出的数组，而导入来的存档「合法但不生效」。
`habits` 从本轮起收敛，**改的时点是它第一次有了写入路径**，不是它的结构变清楚了
（结构从 P2 起一个字没变）。

## 数据迁移（一次性，不可忽略）

nono 在线上已经有进度。线上数据在浏览器 IndexedDB 里，小程序读不到 ——
直接切过去等于清零，违反「什么算好」第 2 条。

线上家长后台已有「导出数据 → 复制 JSON」和「粘贴 JSON → 导入数据」。
迁移路径因此是现成的：线上导出一份 JSON，小程序侧提供一次性导入。

**这要求小程序的存档结构能容纳线上 JSON 的全部字段**，所以 P1 必须先逆出线上数据模型，
再设计存档，不能先画页面。导入是一次性动作，不做双向同步。

**导入界面在 P7 第一段落地（2026-08-14）**：家长端数据段的粘贴框 → 「看看这份数据」
→ 摘要确认 → 整份覆盖。在此之前那 15 条导入规格全绿而**零调用点** ——
「写好了但没人用」是门禁抓不到的一类缺口。**不做反向迁移**：本仓库导出的是存档原文，
导不回线上（线上读 `parentSettings` / `tasks` / `dailyRecords` 那套字段名）。

## 设计假设（已全部拍板）

以下条目影响 P1 及之后的规格表。**六条原本都是 AI 起草的 `待确认`，
到 P7 / P3-c 收尾时全部被代码兑现，最后五条标记于 2026-08-18 摘除**
（PIN 那条在 P7 第一段就摘了）—— 每条后面记的是「在哪一轮落地、落在哪里」，
因为「假设」与「事实」对读文档的人是两件不同的事：
假设可以推翻，事实要改就得改代码。

- **只服务一个孩子，存档单例，不做多档位切换。** P1 落地：storage 只有一个键
  `nono-save`（`miniprogram/app.js:14`），整份存档一条记录。加档位要动的不是某个页面，
  是这个键 —— 所以它是这六条里最贵的一条，也是最该在 P1 就定死的一条。
- **宠物只有一只，可以更换形象，但不能重开或清零等级。** P4 落地：`choosePet`
  只改 `pet.type` 与 `pet.name` 两个字段，**`petLevel` / `petExp` 一个字不碰**
  （`miniprogram/utils/pet.js:268`）。全仓没有清零宠物的函数 ——
  「不做死亡 / 跑掉 / 送走」那条不做的是终局，这条不做的是重开。
- **时间尺度以「天」为主：打卡、连续天数、每日报告都按自然日结算，
  跨日以本机时区 0 点为界。** P1 落地：`dayKey` 用 `getFullYear` 系列而非
  `toISOString`（`miniprogram/utils/dayKey.js:20`），与线上工作台一致。
  **饱腹度是唯一的例外，P4 拍板**：按 6 小时一格衰减，与自然日无关；开心度不随时间变化。
- **漏打卡不影响已获得的积分与勋章，只影响「连续天数」。** P2 落地：
  `habitStreak` 往前数到断掉即止（`miniprogram/utils/habit.js:170`），
  而货币只增不减、`uncheckAndRefund` 是唯一的减法且只退当次。
  这是「温和，不惩罚」在数据上的形状 —— 也是「不做连击断裂的负面提示」的前提：
  没有被清零的东西，才不需要提示它被清零了。
- **家长 PIN 明文 4 位数字存在存档里**（与线上一致，不做哈希），
  **忘了没有找回方式，清空数据是唯一出路**。P7 第一段拍板。
  理由是能读到 storage 的人能读到里面任何东西，哈希只防孩子而孩子看不到 storage；
  代价是设置页不能回显、改 PIN 要输两遍。但补一条线上没有的节流：
  **连错 5 次冷却 60 秒** —— 威胁模型里真实的对手是 5 岁孩子拿着这台手机
  穷举一万种组合（`docs/features/parent/doc.md`）。
- **学习内容（汉字、古诗）随小程序包一起发布，不做远程更新。** P5 落地：
  2000 字与 169 首诗都在 `miniprogram/data/`，全仓 `wx.request` /
  `wx.downloadFile` / `wx.uploadFile` **零调用点**。它与「不做联网请求」互为因果，
  代价是改一个错别字要重新发一次包 —— 家庭自用、走真机预览，这个代价可以接受。
