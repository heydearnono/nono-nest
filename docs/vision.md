# 产品愿景

> 这份文件记录 AI **无法从代码推断**的东西：为什么做、给谁做、什么算好、什么明确不做。
> 标记 `待确认` 的条目是 AI 起草的假设，需要人确认或改写后去掉标记。

## 是什么

给 nono（5 岁）的**成长陪伴工作台**微信小程序。一个入口下有五件事：

- **学习** —— 识字、古诗、数学、阅读、英语，各自有自己的进度与复习节奏
- **自律** —— 每日习惯打卡（起床、刷牙、穿衣、整理……）
- **健康** —— 饮食、喝水、运动、排便、洗澡的记录
- **奖励** —— 打卡产出积分，积分换贴纸、换勋章、换现实中的小特权
- **宠物** —— 一只随互动变化的小伙伴，是上面四件事的情绪出口

外加一个**家长端**：任务管理、积分规则、每日报告、设置，用 4 位 PIN 长按进入。

宠物是其中一个模块，不是整个产品。这一点与本仓库早期版本不同 —— 早期定位是纯宠物养成，
2026-08-11 随线上工作台的功能迁移改为现在的定位。

## 前身：线上工作台

本项目的功能来源是已上线的 PWA <https://xiaoluzhu.net/>（「Nono 工作台」，
manifest 里的自述是「5岁女孩成长陪伴工作台」）。它是 Vite + React 单页应用，
数据存在浏览器 IndexedDB（库名 `nono-workbench`），无后端。

小程序版是**功能迁移**，不是重写产品。判断某个行为该怎么设计时，线上实现是第一参考；
偏离线上行为必须在对应 `doc.md` 里写明理由。

线上已有的内容资产（迁移时直接沿用，不重新收集）：

| 资产   | 规模    | 来源                     |
| ------ | ------- | ------------------------ |
| 汉字库 | 2000 个 | 线上 `characters` 数据包 |
| 古诗库 | 169 首  | 线上 `poems` 数据包      |
| 贴纸   | 140 个  | 线上 bundle 内常量       |
| 成就   | 11 个   | 线上 bundle 内常量       |

规模数字是从线上 bundle 里逐条数出来的，不是界面文案。界面上说的「约 200 个贴纸」
与实际的 140 个不符，以本表为准（依据见 `docs/features/storage/doc.md`）。

## 给谁做

**两类使用者，界面与目标都不同：**

- **nono（5 岁）** —— 主要使用者。不识全字、注意力短、需要即时正反馈。
  界面必须能在「不读长句」的前提下用：大按钮、emoji、颜色区分。
- **家长** —— 配置者与旁观者。关心趋势和报告，不关心动画。
  家长端藏在 PIN 后面，孩子不应该误入。

单一家庭自用。不做多人、不做社交、不做排行榜、不做分享传播。
因此：无账号体系、无后端、无云开发，所有数据存在本机 storage。

## 什么算好

按重要性排序，冲突时上位覆盖下位：

1. **每天想打开一次。** 驱动力是「我的进度在长」和「小伙伴在等我」，不是签到奖励本身。
2. **温和，不惩罚。** 漏一天不清零、不倒扣、不断连击提示羞辱。
   宠物会不开心，但**不会死、不会消失、不会清零进度**。长期不打开只会睡着，回来能恢复。
3. **孩子能独立完成一次互动。** 不需要家长在旁边读屏。
4. **一次互动短。** 单个打卡 10 秒内结束；一次学习不超过 5~10 分钟。
5. **状态可解释。** 为什么涨了积分、宠物为什么不开心，界面上要能看懂，不能只给数字。
6. **家长的配置不该被孩子的操作破坏。** 规则、PIN、任务清单只在家长端可改。

## 明确不做

- **不做真钱内购。** 星光 / 宝石 / 宠物粮 / 勋章是行为记账单位，只能靠打卡产出，
  不能购买、不能充值。这与早期版本「不做货币」的措辞不同：货币做，付费不做。
- **不做付费抽卡。** 贴纸抽取只消耗打卡赚来的勋章，且每日有免费次数上限。
- 不做倒计时催促、推送轰炸、连击断裂的负面提示
- 不做死亡 / 跑掉 / 送走等负面终局
- 不做联网请求（含埋点、崩溃上报、远程配置、内容更新）
- 不做多孩子档位（`待确认`，见下）
- 不上架发布，不申请小游戏类目（个人号无法选择）

## 产品阶段

| 阶段 | 目标                                                            | 状态   |
| ---- | --------------------------------------------------------------- | ------ |
| P0   | 重定位：宪法、愿景、术语表对齐到「工作台」                      | 已完成 |
| P1   | 数据模型 + 存档纯函数 + 线上 JSON 导入函数                      | 已完成 |
| P2   | 自律打卡（`HABIT`）+ 首页最小版                                 | 已完成 |
| P3   | 积分 / 勋章 / 兑换（`POINT` / `REWARD` / `ACHV`）               | 进行中 |
| P4   | 宠物（`PET` / `FULLNESS` / `MOOD`）                             | 已完成 |
| P5   | 学习域五个子页（`LITERACY` / `POEM` / `MATH` / `READ` / `ENG`） | 进行中 |
| P6   | 健康（`HEALTH`）                                                | 已完成 |
| P7   | 家长后台（`PARENT`，含 PIN 长按入口）                           | 未开始 |
| P8   | 语音跟读（可选，需申请 WechatSI 插件）                          | 未开始 |

P1 是关键路径：所有页面都读写同一份存档，结构定错了后面全要改。

P1 只做了**纯函数那一层**（`dayKey` / `save` / `importOnline`）。真正调
`wx.setStorageSync` 的读写包装留给 P2 的首页，粘贴 JSON 的导入界面留给 P7 的家长端 ——
这两件都需要一个页面才有意义。另外 P1 的存档只接线上 19 个顶层键里的 10 个，
积分规则、学习进度、贴纸收藏要等 P3 / P5 定完结构才能进存档，
**所以线上导出的 JSON 原文要留着，届时需要再导入一次**（细节见
`docs/features/storage/summary.md`）。

P2 落地后首页可以打卡了，但**打卡不发放任何积分** —— `starReward` / `petFoodReward`
两个字段已经在存档里躺着，等 P3 来读。这是刻意的：先给孩子看到星星、再在 P3 调整发放
规则，改动就变成了「扣星星」。所以 P2 的首页是「有反馈但不涨数字」的过渡态
（细节见 `docs/features/habit/summary.md`）。

P3 拆成两段。**P3-a（`POINT`）已完成**：打卡发星光与宠物粮、取消扣回、当天流水，
首页顶部有了货币带。**勋章此刻恒为 0** —— 它只有两个产出点（今日全勤、成就解锁），
而今日全勤要 8 条核心 id 全打满，其中 `literacy` / `reading` 要 P5 的学习页、
`exercise` 等要 P6 的健康页才可能被打上。所以 `REWARD`（兑换）现在还换不了东西，
`ACHV`（成就）也还没有触发面。P3-b 的顺序因此依赖 P5 / P6，不是纯粹的「下一步」
（细节见 `docs/features/point/summary.md`）。**P5 首段补上了 `reading`，P6 补上了
`exercise` / `vegetables` / `poop` / `bath` —— 8 条里只剩 `literacy` 没有打卡入口。**

**P4 主动加了一条线上没有的规则：饱腹度随时间衰减，每 6 小时 -1，下限 0。**
线上的饱腹度只升不降，连点几次喂食就永久饱着，宠物粮失去用途，
「小伙伴在等我」（「什么算好」第 1 条）也就无从成立。这是 2026-08-12 的人拍板决定，
不是逆向所得，所以记在这里而不是当成迁移细节。

**只衰减饱腹度，开心度不衰减。**「饿了要喂」是照顾，孩子能立刻解决（打卡赚粮 → 喂食）；
「你不陪我我就难过」是情绪绑架，与「温和，不惩罚」冲突，而且昨天没陪也补不上。
衰减到 0 的唯一表现是界面上的「饿饿」角标 —— 不掉等级、不掉经验、不清零进度，
符合「什么算好」第 2 条与「明确不做」的负面终局条款。
存档因此新增 `pet.lastFedAt`（`SAVE-12` / `IMPORT-10`），结算发生在宠物页的 `onShow`
（细节见 `docs/features/pet/summary.md`）。

**P5 拆成多段，本轮（2026-08-12）只做阅读与英语（`READ` / `ENG`）。** 这两个在线上
几乎没有学习逻辑 —— 填一张表、点一下完成，就是一次打卡，正适合先把「学习域怎么接进
已有的打卡 → 发放 → 成长这条链」验证一遍。识字与古诗要先把 2000 字 / 169 首的数据包
搬进 `data/` 并移植复习调度，数学要 30 道题与六阶段升阶规则，各自一轮。
tabBar 因此多了第三个 tab（`📚 学习`），入口页列五格，未做的三格是灰的
（细节见 `docs/features/learning/summary.md`）。

顺带把 P3-b 的一个缺口填了：`reading` 是今日全勤那 8 条核心 id 之一，现在它有打卡入口了。

**P6（健康）一轮做完，没有第二段。** 四条健康任务在 P2 就已落库，本轮只补了读写它们的那一层
（`utils/health.js` 三个函数 + 一个页面），没有新的数据包、没有新的经验常量
（健康打卡与自律打卡同价，都是 5 点经验）。tabBar 因此有了第四个 tab（`🥗 健康`）——
线上健康是从首页跳进去的普通页面，本仓库把它提成 tab：学习已经是 tab 了，
两件同为「每天要进去一次」的事放在两个层级上，5 岁的孩子要记两套路径
（细节见 `docs/features/health/summary.md`）。

P6 唯一的新原语是 `weekKeys`（`utils/dayKey.js`，`DAY-06` ~ `DAY-09`）：洗澡卡要显示
「本周 N/3」。它同时是 P3-b 周奖励要用的那份键，所以落在 `DAY` 区而不是健康域里。
**`bath` 的 `weeklyTarget: 3` 只做显示、不做门禁** —— 做成「一周只发 3 次」会引出
「第 4 次洗澡要不要给星星」这种要拍板的问题，而它与「温和，不惩罚」的方向相反。

## 与线上的已知差异

| 项           | 线上                                    | 小程序版                           | 原因                                                                       |
| ------------ | --------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------- |
| 存储         | IndexedDB（`idb` 库）                   | `wx.setStorageSync`                | 小程序无 IndexedDB；且本仓库要求运行时零依赖                               |
| 路由         | react-router 17 条路径                  | `app.json` pages + tabBar          | 平台差异                                                                   |
| 语音跟读     | `speechSynthesis` + `SpeechRecognition` | **第一期不做**，降级为手动确认按钮 | 小程序只有 WechatSI 插件，需真实 appid 绑定 + 后台申请，且 PC 端识别不可用 |
| 版本更新提示 | Service Worker                          | `wx.getUpdateManager()`            | 平台差异                                                                   |
| 导出数据     | `navigator.clipboard`                   | `wx.setClipboardData`              | 平台差异                                                                   |
| 复杂粒子特效 | CSS 动画                                | WXSS 动画，过重的降级              | 小程序渲染性能与包体积                                                     |

## 数据迁移（一次性，不可忽略）

nono 在线上已经有进度。线上数据在浏览器 IndexedDB 里，小程序读不到 ——
直接切过去等于清零，违反「什么算好」第 2 条。

线上家长后台已有「导出数据 → 复制 JSON」和「粘贴 JSON → 导入数据」。
迁移路径因此是现成的：线上导出一份 JSON，小程序侧提供一次性导入。

**这要求小程序的存档结构能容纳线上 JSON 的全部字段**，所以 P1 必须先逆出线上数据模型，
再设计存档，不能先画页面。导入是一次性动作，不做双向同步。

## 待确认的设计假设

以下条目影响 P1 及之后的规格表，落地前需要人拍板：

- `待确认` 只服务一个孩子，存档单例，不做多档位切换。
- `待确认` 宠物只有一只，可以更换形象，但不能重开或清零等级。
- `待确认` 时间尺度以「天」为主：打卡、连续天数、每日报告都按自然日结算，
  跨日以本机时区 0 点为界。**饱腹度这一项已在 P4 拍板：按 6 小时一格衰减，与自然日无关；
  开心度不随时间变化。**
- `待确认` 漏打卡不影响已获得的积分与勋章，只影响「连续天数」。
- `待确认` 家长 PIN 忘记后的找回方式：无。清空数据是唯一出路。
- `待确认` 学习内容（汉字、古诗）随小程序包一起发布，不做远程更新。
