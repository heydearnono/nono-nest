# 产品愿景

> 这份文件记录 AI **无法从代码推断**的东西：为什么做、给谁做、什么算好、什么明确不做。
> 标记 `待确认` 的条目是 AI 起草的假设，需要人确认或改写后去掉标记。

## 是什么

一个微信小程序，nono 在里面养一只属于自己的小宠物：孵蛋、喂食、陪玩，看它的状态随时间变化。

## 给谁做

单一用户 nono（家庭成员）。不做多人、不做社交、不做排行榜、不做分享传播。
因此：无账号体系、无后端、无云开发，所有数据存在本机 storage。

## 什么算好

按重要性排序，冲突时上位覆盖下位：

1. **每天想打开一次。** 核心驱动力是「宠物在我不在时发生了变化」，而不是签到奖励。
2. **温和，不惩罚。** 忘记喂食会让宠物不开心，但**不会死、不会消失、不会清零进度**。
   长期不打开只会让它睡着，回来后能恢复。
3. **一次互动 10 秒内结束。** 打开 → 看一眼状态 → 喂一下或玩一下 → 关掉。
4. **状态可解释。** 宠物为什么不开心，界面上要能看懂原因，不能只给一个数字。

## 明确不做

- 不做内购、货币、抽卡、体力值
- 不做倒计时催促、推送轰炸
- 不做死亡 / 跑掉 / 送走等负面终局
- 不做联网请求（含埋点、崩溃上报、远程配置）
- 不上架发布，不申请小游戏类目（个人号无法选择）

## 待确认的设计假设

以下条目影响 P1 及之后的规格表，落地前需要人拍板：

- `待确认` 宠物只有一只，不能重开或重置。
- `待确认` 时间尺度以「小时」为单位感知：离开几小时能看出变化，离开十几小时状态明显下滑。
- `待确认` 孵化是一次性的一段体验，孵出后不再回到蛋的状态。
- `待确认` 不设等级 / 成长阶段，宠物形态固定。
