# 古诗（169 首 + 每周三首 + 会背判定）

- 区名：`POEM`（诗库、每周三首的选诗、复习调度、国学打卡）
- 模块：`miniprogram/data/poems.js`、`miniprogram/utils/poem.js`、
  `miniprogram/pages/poem/`
- 状态：已完成（见 `summary.md`）。本文件的设计与规格表一字未改地落地了，
  只订正了下文一处笔误的 Spec ID 引用；三处偏离线上的取舍全部照写
- 关联愿景：`docs/vision.md` P5 的第三段（古诗），一轮做完
- 顺带产出：存档 `learningProgress` 下新增 `guoxue` 子键（`SAVE-17` / `IMPORT-14`）、
  学习入口页的第三格从灰变亮

## 背景

`docs/features/learning/doc.md` 把国学留成了灰格子（`page` 为空串），
`docs/features/literacy/doc.md`「范围外」第 1 条写明「古诗的调度**与识字不共用**
……古诗要在 `learningProgress` 下加自己的子键，不新增顶层键」。本轮做这件事。

`ACHV` 区的 `poem-10` 成就此刻进度恒 `0`（`docs/features/reward/summary.md`：
「两个子键一出现就自动亮起来」）。本轮就是那个「出现」—— 但它对存档形状提了一个
硬要求，见下文「`mastered` 为什么是存档里的字段」。

### 线上的诗库

`poems-Dy2KFKnl.js` 是纯数据包，零逻辑（除 JSON 外只有
`var e=JSON.parse(\`…\`);export{e as default}`）。逐条数过的事实：

| 项        | 值                                                                        |
| --------- | ------------------------------------------------------------------------- |
| 条数      | **169**，`id` 严格是 `p1` ~ `p169` 且与数组下标一一对应                   |
| 字段      | `id` `title` `author` `dynasty` `content` `type` `grade` `tier`，八个全有 |
| `content` | 句子数组，4 ~ 10 句                                                       |
| `type`    | 169 条全是 `'poem'`，**全仓无一处读取** —— 死字段                         |
| `grade`   | `1` 34 条 / `2` 70 条 / `3` 65 条，标签 `启蒙` / `一年级` / `二年级+`     |
| `tier`    | `required` 109 条 / `extended` 60 条，标签 `必背` / `拓展`                |
| `dynasty` | 唐 121、宋 28、先秦 5、清 4、古代 4、汉 2，其余各 1                       |
| 作者      | 63 位                                                                     |
| 排序      | 按 `(grade, tier)` 分五段，同段内作者聚在一起                             |

五段的分界：`p1` 起 1/必背、`p35` 起 2/必背、`p75` 起 2/拓展、`p105` 起 3/必背、
`p140` 起 3/拓展。**顺序本身是规格**（与 `data/characters.js` 同一条）：
它就是「先学哪首」的教学序列，`data/poems.js` 里不许排序、不许去重。

### 线上的选诗与调度（逆向自 `index-VUOSJfWA.js`）

```js
learningProgress.guoxue = { learnedPoems: [], masteredPoems: [], reviewSchedule: {} };
```

三个函数：`dayNumber(d)` 把时刻锚到当天中午再取 `floor(ms / 86400000)`；
`weeklyIndices(total, d)` 算 `start = (floor(dayNumber / 7) * 3) % total` 并返回
`[start, start+1, start+2]`；`pickPoems` 把池子取成 `tier !== 'extended'`（109 首），
取本周三首加最多两首到期的，复习在前、去重，最后给 3 ~ 5 首。

| 项       | 线上做法                                                             |
| -------- | -------------------------------------------------------------------- |
| 选诗池   | `tier !== 'extended'`，也就是 109 首必背                             |
| 本周三首 | `floor(天序号 / 7) * 3 % 109` 起、连续三个下标，**不落盘**、每次现算 |
| 周边界   | `floor(天序号 / 7)` —— 纪元 1970-01-01 是**周四**，所以周界在周四    |
| 掌握判定 | 点一下「✨ 已会背」即 `masteredPoems.push`，无验证、无退回           |
| 调度     | `reviewSchedule[id]                                                  |     | = 六个日期`，**只在首次学习时写一次** |
| 到期判定 | `some(日期 <= 今天)`，最早那个永远说话                               |
| 复习上限 | 2                                                                    |
| 错误计数 | **没有**。没有「还没背下来」这个入口                                 |
| 当天记录 | `learning.guoxue = { poemId, learned, recited }`，**单数**           |
| 打卡发放 | `pointRules.learning` 的 `stars: 2 / foodPoints: 2`，经验 `8`        |
| 成就     | `poem-10` 数 `masteredPoems.length`                                  |
| 页面互动 | 听读 / 跟读 / 自己表态三种，没有填空、没有选择题                     |
| 目录     | 可以浏览全部 169 首，但**列表行没有 onClick**                        |

线上这一块的问题里，四处直接决定了本轮的取舍：

1. **六档调度是惰性的，比识字那份更死。** 一次写六个日期、判定取 `some(<= 今天)`，
   实际间隔恒为 1 天；而且 `||=` 意味着**这辈子只写一次** —— 识字至少在掌握时重写，
   古诗连重写都没有。于是一首诗从第二天起「永远到期」。
2. **60 首拓展诗结构性不可达。** 选诗池过滤掉它们，目录列表行又没有 onClick ——
   界面上那句「拓展 0/60」永久是 0，`poems_mastered` 的上限也因此是 109。
3. **「今日学习」与「已会背」给一样的东西。** 两个按钮都走同一条发放（一天一次），
   而「已会背」还额外白送一首进 `masteredPoems` —— **谎报严格占优**。
4. **周边界落在周四。** 其余全仓用 `mr()`（周一为起点），只有选诗用
   `floor(天序号 / 7)`。同一个「本周」有两套口径。

另外当天记录是**单数**（`{ poemId, … }`），一天学两首后一首覆盖前一首；
`poem-10` 解锁时不弹 `newMedal`（`updateReading` 弹了），成就静默。

### 数据包的已知缺陷

| 缺陷                                                         | 处理                    |
| ------------------------------------------------------------ | ----------------------- |
| `p17 寻隐者不遇` 与 `p167 寻隐者不遇其二` 正文**逐字相同**   | 照搬不修，见下文        |
| `p114 过故人庄`（4 句）是 `p169 过故人庄其二`（6 句）的前缀  | 照搬不修                |
| `p68 题西林壁`（苏轼）标 `dynasty: '唐'`                     | **改成 `'宋'`**，见下文 |
| 12 首的 `dynasty` 拼不出「X 代」（`古代` / `先秦` / `北朝`） | 不拼那个字，见下文      |
| 词被标成 `type: 'poem'`                                      | `type` 不转抄，问题消失 |

**`p68` 的朝代改，其余照搬。** 识字那一轮对 1107 条空例句与 9 条可疑拼音的处置是
「照搬不修」，理由是「改它等于分叉出第二份字库」。这里的分界是**缺内容还是错内容**：
空例句缺了页面不显示，可疑拼音要另找权威源逐条核对 2000 条；而「苏轼是唐朝人」
是一条会被显示出来、且无争议错的事实，改一个字段不需要第二份数据源。
这不违反「内容资产迁移时直接沿用，不重新收集」—— 没有重新收集，只订正一处。

**两处重复的正文不动。** 两首「其二」都在 `extended` 段，而拓展诗要等 109 首必背
全部会背才解锁（见下文），所以本轮乃至今年之内都碰不到它们。真要删，删的是
数据包的两条记录，那会让 `id` 与下标不再一一对应 —— 代价比留着大。
留下的后果写在这里：**拓展那 60 首里有两首与必背重复**。

**朝代不拼「代」字。** 线上把 `${dynasty}代${author}` 拼给语音朗读，于是有
「古代代佚名」「先秦代诗经」。本轮显示成 `{dynasty} · {author}`（`唐 · 李白`），
那 12 条自然就对了 —— 不是修数据，是不做那次拼接。

## 设计

### `data/poems.js`：169 首，七个字段

```js
export const POEMS = [
  {
    id: 'p1',
    title: '咏鹅',
    author: '骆宾王',
    dynasty: '唐',
    content: ['鹅鹅鹅', '曲项向天歌', '白毛浮绿水', '红掌拨清波'],
    grade: 1,
    tier: 'required',
  },
];
```

`type` 不转抄（169 条取值全同且全仓无读取点，是死字段 —— 与 `defaultHabits.js`
不转抄 `subCategory` / `module`、`data/rewards.js` 不转抄 `needsConfirm` 同一条）。
`export default` 改成具名 `POEMS`（与 `CHARACTERS` / `LEARNING_MODULES` 一致）。
`JSON.parse(模板字符串)` 展开成真正的对象字面量（常量区不许有调用）。

`grade` 与 `tier` 沿用线上字段名，不改写成中文语义的新名字
（`docs/glossary.md` 已写明这两个是**数据字段名**）。它们的中文标签
（`启蒙` / `一年级` / `二年级+`、`必背` / `拓展`）不进 `data/` ——
那是渲染用的映射，落在 `utils/poem.js`，页面拿到的卡片上已经带着 `gradeLabel`
与 `tierLabel`（与 `literacyState` 给卡片算好 `emoji`、`healthState` 给
`poopIcons` 同一条分工）。

### 本周三首：顺序取未学的，落盘

**这是本轮第一处偏离线上。**

```js
learningProgress.guoxue.weekly = { weekKey: '2026-08-10', ids: ['p1', 'p2', 'p3'] };
```

选法是**从选诗池里按数据包顺序取最前面三首还没学过的**，与识字「取未学过的字里
语料顺序最前的两个」逐字同构。结果写进 `weekly`，`weekKey` 是 `weekKeys(now)[0]`
（本周周一的日期键，与周奖励的水位同一形状）。

线上那个 `floor(天序号 / 7) * 3 % 109` 的滑动窗口有三个后果，本轮三个都不要：

- **缺席一周，那三首要等约 8 个月才回来**（窗口转一圈 36 ~ 37 周）。
  顺序取未学的没有这个问题：没学的还在最前面，下周第一个就是它。
- **窗口硬前进，启蒙阶段的孩子第 12 周撞上一年级、第 25 周撞上《登高》。**
  按未学顺序取，`grade: 1` 的 34 首会老老实实排在前面 —— 分级由数据包的顺序
  保证，选诗层不需要知道 `grade`（与识字「字频序由数据包保证，调度层不知道字频」同一条）。
- **周边界在周四。** 本轮用 `weekKeys(now)[0]`，与洗澡卡的「本周 N/3」、
  周奖励的水位是同一份口径。全仓只有一个「本周」。

**为什么要落盘。** 「顺序取未学的三首」是 `poems` 键集的纯函数，不落盘也算得出来 ——
但那样孩子周一学完 `p1`，周二列表就变成 `p2` / `p3` / `p4`，**学一首冒一首**，
「每周三首」就成了「一天想学几首都行」。落盘让这三首在一周内固定：`p1` 学过了
仍留在列表里、标成已学，`p4` 要等下周一。这个字段是**水位**，与
`bonuses.allDone`、`lastWeeklyBonusWeek` 同一类，不是可以重算的快照。

写入方只有一个：`studyPoem` 在动手之前先刷一次水位（`weekKey` 与本周不符就重选）。
**页面不必额外调一个 `refreshWeekly`** —— 那就是「留给页面两步走」，
`docs/features/reward/doc.md` 已经把这条判断钉过一遍。整周没学过诗的那些周
因此从不落盘，`poemState` 读到过期的 `weekKey` 时**当场按同一个 helper 算一遍**
（渲染宽容）。两条路径共用那个 helper，所以落盘的与显示的不可能不一致（`POEM-30`）。

### 一首诗一条记录，四个字段

```js
learningProgress.guoxue.poems = {
  p1: { step: 2, due: '2026-08-16', wrong: 1, mastered: false },
};
```

线上那三个平行结构（`learnedPoems` / `masteredPoems` / `reviewSchedule`）是它
1、3 两个毛病的病根，与识字那五个结构同一个病。一首诗一条记录：

- `step` —— 连续说「已会背」的次数，`0` ~ `5`。`1` ~ `4` 各对应间隔表的一档，
  `5` 表示已会背；`0` 是「上次说还没背下来，今天重来」。
- `due` —— 下次出现的日期键。已会背的是空串，永不再出现。
- `wrong` —— 累计说过几次「还没背下来」，只用来给同一天到期的诗排先后。
- `mastered` —— 已会背没有。**这个字段是冗余的**，理由见下一节。

四个状态与 `docs/glossary.md` 的四个词一一对上：`unseen` 是 `poems` 里没这个键、
`learning` 是有键且 `step < 5`、`mastered` 是 `step === 5`、`wrong > 0` 与前三个正交。

### `mastered` 为什么是存档里的字段

`ACHV` 区的 `poems_mastered` 判据已经在 `miniprogram/utils/reward.js` 里写好了：

```js
poems_mastered: (save) =>
  Object.values(save.learningProgress?.guoxue?.poems ?? {}).filter((p) => p?.mastered).length,
```

`reward.js` **不能** import `poem.js`：依赖链是 `poem.js → pet.js → reward.js`，
反过来就成环。所以「这首诗会背了没有」必须是**存档上直接读得出的事实**，
不能是「知道古诗的档位表才算得出来」的判断。

代价是 `mastered` 与 `step === 5` 说的是同一件事，脏存档里它们可能对不上。
处置：**读取路径以 `step` 为准**（`poemState` 现算，`POEM-28`），写入方只有
`studyPoem` 一个、每次都同时写两个字段，所以正常路径上不可能分叉。
换来的是 `ACHV` 区不必回头改判据 —— `docs/features/reward/summary.md`
承诺过「古诗那一轮不必回头改 `ACHV`」，这一节就是履约。

### 间隔表四档、跨 26 天、五次表态

**这是本轮第二处偏离线上**，修的是上文问题 1 与 3。

```js
const REVIEW_STEPS = [1, 3, 7, 15]; // 天
```

- 说「✨ 已会背」：`step + 1`，`due = dayKeyAfter(now, REVIEW_STEPS[新 step - 1])`。
  走完 `15` 那一档（`step` 从 `4` 变成 `5`）才算**已会背**，`due` 置空、`mastered` 置真。
- 说「😅 还没背下来」：`step` 回 `0`，`due` 是今天，`wrong + 1`。

`step` 是「连着说对了几次」而不是间隔表的下标 —— 与识字同一套语义，
所以 `docs/glossary.md` 里 `step` 只有一条定义。档位与天数因此差一位
（`step` 为 `1` 时等 `REVIEW_STEPS[0]` 天），跨过四个间隔要**五次**表态、
最快 1 + 3 + 7 + 15 = **26 天**。

**为什么是四档 26 天，而不是照识字的六档 58 天。** 两个数都不是抄来的，要说清：

- 流量不同。识字每天引入 2 个字（14 个/周），古诗每周引入 3 首 ——
  复习队列的压力小了近五倍，档位可以更疏、档数可以更少。
- `poem-10` 成就要 10 首会背。26 天一首的话，第一首在第 4 周会背、
  之后每周三首进流水线，第 10 首大约在第 7 周；用 58 天要等 4 个月。
  成就是给孩子看的动机（`ACHV-05` 同一条判断），4 个月太久。

`1 / 3 / 7 / 15` 本身是识字那六档的稀疏版（去掉 2 与 4、把 14 挪到 15 凑满两周），
不是新拍的一套节奏。

### 两个按钮，「今日学习」那个不要

线上三个动作里「📖 今日学习」与「✨ 已会背」发一样的东西，于是谎报占优。
本轮只有一对**自我表态**按钮，与识字的 `我认识 ✅` / `还不太会 🔄` 同构：

| 按钮            | 效果                                   |
| --------------- | -------------------------------------- |
| `✨ 已会背`     | `step + 1`，够五次就是会背             |
| `😅 还没背下来` | `step` 回 `0`、`due` 今天、`wrong + 1` |

**两个按钮都算「今天学了国学」，都打卡。** 说「还没背下来」也发星光 ——
「温和，不惩罚」（`docs/vision.md`「什么算好」第 2 条）：诚实地说没背下来
不该比谎报亏。谎报的收益因此只剩「早一点看到会背的数字」，而那个数字要熬 26 天，
一天之内谎报不出来。

打卡条件因此是**当天表过任意一首的态**（不论说的是哪一句）。
识字要「新字满 2」是因为那一格的定义是「每天 2 个新字」；国学这一格的定义是
「每周 3 首」，一天表一次态就够了 —— 线上也是点一下就发。

`studyPoem` 一个函数收两种表态，不是 `recitePoem` / `forgetPoem` 两个：
两条路径的差别只有「`step` 往前一档还是回到 0」，其余（当天去重、写记录、打卡发放）
完全相同（与 `gradeChar` 收两种评分、`toggleHealth` / `setHealth` 按形状分同一条）。

### 拓展 60 首：109 首必背全部会背才解锁

**这是本轮第三处偏离线上**，修的是上文问题 2。

选诗池默认是 `tier === 'required'` 的 109 首（抄线上）。**109 首全部
`mastered` 之后，池子变成全部 169 首。** 那条分支跑得到（不是不可达代码），
只是 nono 要走到很久以后 —— 每周 3 首、109 首至少 36 周引入，加上每首 26 天，
最快也在一年以后。

代价是页头那句「拓展 0/60」会长期是 0。这与 `ACHV` 区那两行长期停在 `0/10`
的进度条是同一类代价，且比线上强一档：线上那个 0 是**永久**的（池子过滤 +
目录不可点，两道墙），本轮那个 0 有一条走得通的路。

**为什么不给目录列表行加 onClick。** 那样拓展诗当即可达，但「本周三首」的推荐
就失去约束力 —— 想跳就跳。5 岁孩子需要的是「今天该学哪首」有唯一答案
（「什么算好」第 3 条：孩子能独立完成一次互动），不是一份 169 行的菜单。
目录页本轮也不做（见「范围外」）。

### 页面读到的两个列表

```js
poemState(save, key, now) -> {
  weekly,        // 本周三首的卡片（学过的标成已学、今天到期的带标记）
  reviews,       // 别的周引入、今天到期的，最多 2 首，wrong 多的在前
  required,      // { learned, mastered, total: 109 }
  extended,      // { learned, mastered, total: 60 }
  extendedOpen,  // 拓展解锁了没有
  done,          // 今天这一格打过卡没有
}
```

`weekly` 与 `reviews` **互不重叠**：本周三首里今天到期的那首留在 `weekly`
（带一个到期标记），不再出现在 `reviews` —— 同一张卡片在一屏里出现两次，
孩子会以为是两首诗。

**当天表过态的诗，当天不再进任何列表**（`weekly` 里仍在，但标成今天学过了），
再次 `studyPoem` **原样返回**（对象同一性）。这条同时解决了「还没背下来」的循环：
那首诗 `due` 是今天，不拦的话它会在同一次会话里一直回到队列顶上
（与 `LITERACY-13` / `LITERACY-14` 是同一对）。

已会背的诗既不进 `weekly` 也不进 `reviews`：它不再是未学的（不会被选中），
`due` 是空串但 `step === 5` 把它从到期队列里排除。

卡片形状：

```js
{
  (id,
    title,
    author,
    dynasty,
    content,
    grade,
    tier,
    gradeLabel,
    tierLabel,
    step,
    mastered,
    wrong,
    learned,
    dueToday);
}
```

`learned` 是「`poems` 里有这个键」，`dueToday` 是「今天该复习」。两个布尔都由
`utils/` 算好 —— 页面不写 `step === 5`，也不比日期字符串。

### 当天记录长出 `learning.guoxue`

```js
days['2026-08-13'] = {
  checks: { guoxue: { at: 1754… } },
  ledger: [ … ],
  learning: {
    guoxue: { poems: ['p1'] },   // 今天表过态的诗，说「还没背下来」的也在
  },
}
```

**一个数组，不是线上那个单数的 `{ poemId, learned, recited }`。** 线上一天学两首，
后一首覆盖前一首。这里记的是「今天表过态的诗」，不是「今天学的那首」——
它有两个读取点：打卡判据与当天去重。

不拆成 `newPoems` / `reviewed` 两个列表（识字拆了）：识字拆是因为打卡分子只数新字，
国学的打卡分子是「表过态没有」，一个列表就够 —— 拆开会多一个没人读的字段。

### `utils/poem.js` 的两个纯函数

```js
poemState(save, key, now) -> { weekly, reviews, required, extended, extendedOpen, done }
studyPoem(save, key, poemId, recited, now) -> save   // recited: true 已会背 / false 还没背下来
```

依赖方向 `poem.js → pet.js → point.js → habit.js → data/`，与 `literacy.js` /
`learning.js` 同层。`poem.js` **不 import `reward.js`**（结算由 `pet.js` 末尾的
`settleDay` 负责，见 `docs/features/reward/doc.md`）。

`poemState` **不抛错**（渲染路径宽容）：`habits` 里没有国学任务时 `done` 为 `false`、
存档里 `step` 是坏值时收敛、`poems` 里有不在诗库里的 id 时那条不进任何列表
（导入来的脏 id，渲染不出卡片）。`now` 非有限数时**用落盘的 `weekly.ids`**、
没有落盘就给空数组 —— 不抛错，也不去猜「本周」是哪一周。

`studyPoem` 严格：未登记的 `poemId` 抛 `RangeError`（按钮是 `poemState` 渲染出来的，
传别的值只可能是代码写错）、没有对应任务抛 `RangeError`、`now` 非有限数抛 `TypeError`
（`AGENTS.md` 第 5 节第 6 条）。

发放走 `checkAwardAndGrow(save, key, habit.id, now, 8)`，学习域五个模块同价。
**发放先行、记录后写** —— `day` 从发放后的存档里取，`checks` / `ledger` / `learning`
三个兄弟键就不可能互相覆盖（P6 起的做法，`LITERACY-19` 同一条）。

### 页面

| 元素     | 内容                                                            |
| -------- | --------------------------------------------------------------- |
| 顶部     | 「必背 N/109 · 拓展 N/60」+「会背 N 首」，今天打过卡的加一个 ✅ |
| 本周三首 | 三张卡，学过的角上打勾，今天到期的标「该复习啦」                |
| 到期复习 | 最多两张卡，没有时整段不出现                                    |
| 卡片     | 标题 + `朝代 · 作者` + `启蒙`/`必背` 两个角标 + 逐句排开的正文  |
| 两个按钮 | `✨ 已会背` / `😅 还没背下来`                                   |
| 空态     | 两段都空时显示「这周的诗都学过啦 🎉」                           |

`wx.navigateTo` 从学习入口页进来（不是 tab），所以取初值用 `onLoad` ——
与识字页一致。表态后 `setData` 重渲染，不重进页面。

正文**逐句一行**排开（`content` 本来就是句子数组），不做「点某一句设为当前句」——
那是线上为逐句跟读做的，而跟读本轮不做。

**不做语音朗读与跟读。** `docs/vision.md` 已写明第一期降级为手动确认，
P8 才评估 WechatSI。线上那个逐句/整首两种模式、`threshold: .6` 的评分
（子串匹配，一个字就给 1.0）也一并不做。

`POEM-06` 是本轮偏离线上最要紧的一条：线上窗口硬前进，缺席一周那三首要等约 8 个月
才回来。没有这条规格，下一个人「按线上抄回去」不会有任何东西报警。

`POEM-11` 与 `POEM-18` 是一对：说「还没背下来」照样打卡照样发星光。
线上没有这个入口，而线上那两个按钮发一样的东西 —— 于是谎报占优。

`POEM-24` 钉住「拓展诗有一条走得通的路」。它是本轮唯一一条要构造
「109 首全部会背」的存档才能测的规格，但少了它，下一个人删掉那条分支时
门禁不会响 —— 而线上正是那样（60 首永久不可达）。

`POEM-28` 的「`mastered` 以 `step` 为准」是两个冗余字段的仲裁规则，
理由（`reward.js` 不能 import `poem.js`）见上文。

## 范围外

- **不做语音朗读与跟读。** 线上那套逐句/整首两种模式、`threshold: .6` 的子串匹配
  评分（一个字就给 1.0）全部不做。`docs/vision.md` 已写明第一期降级，P8 才评估。
- **不做 169 首的目录页。** 线上那份目录的列表行没有 onClick，是个只能看的长列表；
  而给它加上点选会让「本周三首」失去约束力（见上文）。
- **不做「点某一句设为当前句」。** 那是为逐句跟读做的交互，跟读不做它就没有读取点。
- **不做填空、默写与选择题。** 线上没有，且它们要另一份「哪个字可以挖掉」的数据。
- **不做诗意讲解与注释。** 数据包里没有这两个字段，硬做要另找内容源。
- **不把 `guoxue` 加进核心名单。** `data/defaultHabits.js` 里它的 `core` 仍是 `false`，
  今日全勤仍是七条（`docs/features/reward/doc.md` 刚把名单从八条收敛成七条，
  加一条要重新拍板全勤的分母）。
- **不做已会背的诗重新学。** 会背是终态，没有退回入口 —— 与识字一致，
  真要重学是家长端（P7）的事。
- **不做取消国学打卡。** 与 `LEARN` 区一致：学习打卡不给撤回入口。
- **不做每周首数与档位表可配。** 每周 3 首、`[1, 3, 7, 15]` 都是常量，不进 `parent`
  设置（线上也没有这个开关）。真要可配是 P7 的事。
- **不修数据包里两处重复的正文与 12 条拼不出「X 代」的朝代。** 见上文的取舍；
  只订正 `p68` 的一个字段。
- **不做首页显示古诗进度。** `dayProgress` 的分母仍只数 `category === 'habit'`。
- **不做数学。** 入口页那一格仍是灰的，`math-10` 成就进度仍恒 `0`。
