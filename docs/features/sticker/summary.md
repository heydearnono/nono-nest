## 实现要点

**`id` 写死在 `data/stickers.js` 的字面量里，不由下标算。** 直接原因是
`AGENTS.md` 第 3 节 —— `padStart` 是计算，常量区不许有。它顺带修掉线上一个静默缺陷：
`stickerCollection` 的键就是这些 id，线上给 `mo` 排一次序，历史收藏册的每一个键
都会对不上，140 张全变「没抽到」而不报任何错。写死之后重排只改显示。
所以本份的「顺序即规格」是三份数据包里**最弱**的那一条 —— 头注释写明了这个差别，
不要因为 `characters.js` / `poems.js` 不可动就以为它同样不可动。

**随机源不注入，用种子现算。** 三个候选（页面传 `random()` / 页面传 `nonce` /
种子现算）在 `doc.md` 里列了代价，选第三个，与 `math.js::shuffleSeed`
（`miniprogram/utils/math.js:194`）同一条先例。种子吃 `` `${日期键}|${已抽总次数}` ``，
**已抽总次数是 `Object.values(收藏册)` 求和、不落新字段** —— 收藏册本身就记着
每张抽到过几次，再存一个计数器就是同一笔数据两个来源（与 `reward.js`
「进度每次现算，不存」同一条）。

代价是「同一份存档、同一天、第 N 次抽必然是同一张」。它在界面上**观测不到**：
抽取是不可撤销的写入，抽完第 N 次就只能抽第 N+1 次，没有「回到抽之前再抽一次」
这条路径。而它在测试里是白拿的好处 —— **`tests/sticker.test.js` 一条桩都没打**。

**加权抽取三处改写，只改可靠性不改行为**：`Math.random()` 换成线性同余取高位
（与 `math.js:227` 同一组参数）、浮点 `cursor` 换成整数 `roll`（线上连减 140 次浮点
权重，末步可能因累积误差落进兜底分支）、判 `roll < 0` 而不是 `cursor <= 0`
（`roll` 从 `0` 起，权重 55 的第一条要吃掉 `0 ~ 54` 这 55 个值，判 `<= 0` 只让它吃掉 `0`）。
**只从未拥有的里抽照搬** —— 线上少见的一处好设计，前 140 次必不重复。

**勋章抽是「货币只由 `point.js` 改」的第八个执行点。**（已有七处：打卡、取消、全勤、
周奖励、兑换、成就解锁、驳回退款。）线上 `--e.currency.medals` 一句就完了、不进流水，
那是这条不变式在线上的第二处破口。流水的 `reason` 带贴纸名字，家长在每日报告里
能看见勋章花在哪儿了。**免费抽货币一分不动、流水一行不加**，只推
`lastFreeStickerDate` —— 一次纯粹的水位迁移（与 `resolveRedemption` 的 `'done'` 同形）。

**顺序先抽后扣**：`reason` 里要有名字，就得先知道抽到哪一张。抽不动的两个分支
在扣之前 `return` 入参，所以不存在「扣了勋章没抽到」的中间态。

**「键存在即拥有」，值只用来数几次。** 这是同一条纪律在全仓的第三次出现
（`days[].checks` 的「键存在即已打卡」、`rewardFlags` 的「缺键 = 启用」）。
`SAVE-25` 把 `0` / 负数 / 非数的键整条丢掉，读取侧于是**只判键在不在**，
不需要线上那个 `filter(t => e[t] > 0)` 的第二道判据。**未知 id 原样留在存档里**
（收敛层零 import，认不出谁登记过），**忽略它的是 `stickerState`**（`STICKER-06`）。

**页面拆成第 13 个 page，不做奖励中心里的一个 section。** 线上是后者
（`:685787`，挂在兑换卡与待确认之间）。判据不是只读性（抽贴纸是写入口），
是**两块界面共用多少数据**：奖励中心的四段共用同一份勋章余额与
`redemptions` / `achievements`，而贴纸只共用**勋章余额一个数**。
140 格 + 类别筛选 + 揭示层塞进去会让 `reward.wxml` 从 69 行长到 250 行以上，
而两边没有一处要一起改。`app.json` **仍然只有四个 tab**。

**未拥有的格子显示 `❓`，不是灰掉的 emoji。** 线上 `opacity-20 grayscale`
仍把 emoji 露出来了，于是 140 张一眼看完、抽取只是把它点亮。`❓` 让
「抽到才知道是什么」成立。代价是家长问「还差哪些」时这一页答不上来 ——
那不是这一页要回答的问题。

## 与 `doc.md` 的偏差

**类别筛选在 JS 里算，不在 WXML 里用 `wx:if`。** `doc.md` 只写了「七个 chip，
页面字段，不落盘」。实现时发现 `wx:for` 里套 `wx:if` 会给不显示的格子留下空占位，
五列网格立刻塌 —— 于是页面多一个 `shown` 字段，`render()` 与 `onTapCategory`
两处各算一次。筛选函数 `filtered(items, category)` 是模块级纯函数、不读 `this.data`。

**`stickerState` 多返回 `medal.balance`，不只 `ready`。** `doc.md` 的返回值清单里
`medal` 只说了「带余额」，没说拆两个字段。按钮上那句「还有 N 枚」要数字，
而「够不够」这个判断不能让页面重做一遍 `>= 1` —— 两个都给。

**`STICKER-02` 的类别 `total` 顺序按段序，不按 `CATEGORY_LABEL` 的字面量顺序。**
两者恰好一致（`animal` / `food` / `nature` / `cute` / `star` / `fantasy`），
所以 `Object.entries(CATEGORY_LABEL)` 直接生成六项就对了 —— 但这是**巧合不是保证**。
测试里同时断言了六类 `total` 求和等于 140，改动 `CATEGORY_LABEL` 时那一条会先响。

**页面用 `onLoad` 而非 `onShow`。** 贴纸乐园是 `navigateTo` 进来的独立页，
不是 tab 页，没有「切回来要重算」这条路径；而抽取后的重算走 `render()`。
与 `pages/reward/reward.js` 刻意用 `onShow`（跨天回前台要补结算）的理由正好相反，
两处都在头注释里写了理由。

**奖励中心那个入口做成一整行的 `.entry`，不是第四张卡。** 三张兑换卡是横向三列，
再塞一张会挤，而且它跳页、不花勋章 —— 形状不一样才不会被当成第四张卡。

除此之外没有偏离。

## 与线上的五处偏离

`doc.md`「线上的贴纸系统」列了五个直接决定取舍的问题，逐条的处置：

1. **抽取扣勋章不进流水**（`:282698`）→ 走 `postLedger`，`reason` 带贴纸名字。
   `STICKER-11` 断言流水多了一行，**不是**断言 `currency.medal` 变成 `2` ——
   后者会让线上那种实现全绿。
2. **id 由数组下标算**（`:269915`）→ 写死在字面量里，重排不再改 id。
3. **收藏册的值可能是 `0`**（线上自己用 `> 0` 过滤，`:677950`）→ `SAVE-25` 在收敛层
   把这些键整条丢掉，读取侧只判键的存在性。
4. **掉落装饰用有偏的洗牌**（`sort(() => Math.random() - .5)`，`:270420`）→
   掉落装饰整件不做（「范围外」），所以这个缺陷连着它的载体一起没有了。
5. **两句提示是死代码**（按钮 `disabled`，`:679622`）→ 两个按钮**都不 `disabled`**，
   点了照 `reason` 给「今天的免费抽用过啦，明天再来」/「勋章不够，先去打卡赚一枚」。
   与奖励中心的兑换卡、宠物页的喂食按钮同一条。

## 对后续 feature 的影响

- **数据搬迁的名单空了。** 线上 19 个顶层键：接了 16 个，永久不接 3 个。
  下一次线上导出的 JSON 进来时，**不再有「这个键要等某一轮」这句话**。
  再有新键只可能来自线上继续开发，而线上已经不动了。
- **`STICKER` 区不阻塞任何东西，也不被任何东西阻塞。** 抽贴纸不在打卡路径上，
  `settleDay` / `checkAwardAndGrow` 一行没改。
- **首页 toast 那条警告仍然挂着。** `docs/features/reward/summary.md:103` 说
  「再加第五种产出时 `checkedTitle` 要改成表驱动」—— 贴纸是勋章的**消耗**
  不是打卡的产出，没到那个临界点。那条留给真的往打卡里加第五种产出的那一轮。
- **`RARITY_WEIGHT` 与「每天一次」是常量，不进存档。** 家长端要调的是
  「一天该完成几项」，不是抽卡概率（「范围外」）。想做的话要先新开顶层键，
  而那会把 `rewardFlags` 那种「只存布尔」的克制丢掉。
- **抽满 140 张之后的行为已经钉住了**（`STICKER-15`）：从全表抽、`count + 1`、
  `isNew: false`。**不做重复贴纸折算** —— 折算要拍板「几张换一枚」，
  而那让抽满之后的抽取变成一门生意。
- **`@keyframes` 现在有两处**（`pet-bounce` 与 `sticker-pop`），两处各自独立。
  第三处出现同一形状时再考虑抽公共层（与 `english.wxss` 头注释同一条）。
- **P8（语音跟读）是唯一未开始的阶段**，且它卡在 WechatSI 插件的后台申请上，
  不卡在代码上。
