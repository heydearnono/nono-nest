# 时段问候语

- 区名：`GREET`
- 模块：`miniprogram/utils/greeting.js`
- 状态：已实现
- 关联愿景：`docs/vision.md` P0

## 背景

首页需要一句随时段变化的问候语，让 nono 每次打开都感觉小伙伴「知道现在几点」。

这条规则本身很小。它真正的作用是**当作 AI 先行机制的样板**：
纯函数 + 规格表 + Spec ID + 测试引用，这条链路先在最简单的规则上跑通，
后续饱腹度、开心度等复杂规则照抄同一形状。

本文件是在代码已存在之后补写的（见 `summary.md` 的偏差说明）。

## 设计

单一纯函数，输入小时数，输出问候语字符串：

```js
greetingFor(hour) -> string
```

- 不读 `Date.now()`，小时数由页面层传入 —— 见 `AGENTS.md` 第 3 节的纯函数区约定
- 按小时数落进 5 个时段区间，区间左闭右开
- 文案里出现「糯糯」时指用户 nono，不指宠物（见 `docs/glossary.md`）

## 行为规格

| Spec ID  | 输入 `hour`                             | 期望输出                 |
| -------- | --------------------------------------- | ------------------------ |
| GREET-01 | 0 ≤ hour < 6                            | `夜深了，小宠物在打呼噜` |
| GREET-02 | 6 ≤ hour < 11                           | `早上好，糯糯`           |
| GREET-03 | 11 ≤ hour < 14                          | `午安，该吃饭啦`         |
| GREET-04 | 14 ≤ hour < 18                          | `下午好，一起玩吧`       |
| GREET-05 | 18 ≤ hour ≤ 23                          | `晚上好，糯糯`           |
| GREET-06 | 非 0–23 整数（负数、≥24、小数、字符串） | 抛 `RangeError`          |

区间边界值（0/5/6/10/11/13/14/17/18/23）必须逐个断言，
时段划分改一次就容易错一个边界，这是本规则唯一的风险点。

## 范围外

- 不做节日 / 生日 / 天气相关文案
- 不做随机文案池（同一时段固定一句，便于测试与预期）
- 不根据宠物状态改文案 —— 那属于 `FULLNESS` / `MOOD` 区，不在此处耦合
