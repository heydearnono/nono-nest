## 实现要点

**`core` 落在任务元素上，不在 `utils/` 的常量数组里。** 线上 `rr` 是一个与 `tasks`
平行的 id 数组，家长删掉 `poop` 之后 `rr` 里还有它 —— 全勤于是永久不可能达成。
写成任务自己的字段之后，「哪些算核心」与「这条任务还在不在、还启用不启用」
是同一份数据。`listCore` 同时过滤 `core` 与 `enabled`，所以分母跟着启用状态变
（`POINT-25`），七条全被停用时不算全勤（`POINT-26`）。

**`post` 导出成 `postLedger`，成为货币变动的唯一入口。** 本轮有四处新的货币产出
（全勤、周奖励、成就解锁、兑换），四处各自 `{ ...save, currency }` 会让账与余额悄悄分叉。
导出一个「原始」函数看着比 `checkAndAward` 那种成对封装弱，但它换来一条更强的不变式：
**`save.currency` 只可能被 `point.js` 改，而它每次改都追加一条流水。**
线上的成就勋章不写流水，于是「流水加起来等于余额」在线上不成立 —— 本轮不继承这个毛病。

**十一条判据按 `condition` 注册（`JUDGES`），与 `health.js` 的 `FIELDS` 同构。**
常量表说「用哪条判据」，怎么算在注册表里。少注册一条抛 `RangeError` 而不是静默返回 0 ——
一条永远 `0/N` 的成就在界面上看不出是 bug 还是「还没达成」。

**达标日只有一个函数。** `isQualifiedDay` 同时喂给周奖励与 `full-week` 成就，
`WEEKLY_BONUS.minDays` 是 import 来的、不是重打的 `5`。线上那两套口径
（核心项 5/8 与「自律 + 学习的 60%」）算同一件事却能给出不同答案，
这是 P5 识字那一轮的教训的同一条：**共用判据要共用的是函数。**

**`settleDay` 挂进 `checkAwardAndGrow`，不留给页面。** 四条打卡路径（自律、健康、
学习表单、识字）全走这个函数，所以一处挂上等于五个页面一起接上（`REWARD-13`）。
线上正是在四个调用点各写一遍成就与全勤结算，漏一处就是一类打卡不发勋章。
它排在涨经验**之后**：`pet-5` 读 `pet.petLevel`，这次打卡刚好升到 5 级时同一次调用就该解锁。

**进度每次现算，不存。** 线上存 `medalProgress` 快照且解锁后不再更新
（`if (已解锁) continue` 在写进度之前），已解锁成就的进度条永远停在解锁那一刻。
没有快照就不会有停住的快照。代价是 `achievementState` 每次都全表扫一遍 ——
十一条判据里最贵的是 `countDays`（一年 365 个键），可接受。

## 与 `doc.md` 的偏差

**`rewardState` 多返回 `coreDone` / `coreTotal` 两个字段。** `doc.md` 原本只写了
`weekBonus` 与 `allDone`，但顶部那句「今日 N/7 项全满」的分母跟着启用状态变，
页面不能写死 `7`。已回填进 `doc.md` 的返回值清单。

**`postLedger` 比 `doc.md` 的签名少一个参数。** 私有的 `post` 原本收一个已经建好的
`day` 对象，四个新调用方手里都没有 —— 改成从 `save.days?.[key]` 自己取。
同时 `{ ...zeroAmount(), ...amount }` 让调用方可以只传变动的那一种货币，
每条流水仍有四个币种字段。

**`ACHV-01` 的期望改了：`pet-5` 的进度是 `1` 不是 `0`。** 宠物等级的初始值就是 1 级，
空存档的进度条显示 `1/5` 是对的 —— 那只小伙伴确实已经存在。把它按到 0 要给这一条
单独减 1，那就是「同一份数据两套口径」，正是本区在别处一直躲开的毛病。
规格表与散文都已改。

**toast 弹哪一条按「结算前后两份存档的水位差」判断，不读 `*State`。**
`doc.md` 只写了优先级（勋章 > 周奖励 > 成就）。实现时发现直接读
`rewardState().allDone` 会把「今天早些时候在首页发过的那枚全勤」也说成本次刚发的，
于是每次进奖励中心都恭喜一遍。比两个水位是适配层的事，判据仍然只在 `utils/` 里。

**首页的入口做成「整条货币带可点」，不是一个独立按钮。** 四种货币占满一行之后
再塞一个按钮会挤，而整条带子是个大得多的靶（「什么算好」第 4 条）。
右端一句「换奖励 ›」提示还能往下走。

除此之外没有偏离。三处刻意偏离线上（七条核心项、申请即扣勋章、`char-50` 数学过）
与第四处（解锁勋章进流水）都在 `doc.md` 里写明了理由。

## 一处被撞出来的既有测试

`LITERACY-26` 原本断言「当天流水恰好一条」。它构造的是「2000 字全学过」的存档，
而那份存档顺带满足 `char-50` —— 挂上结算之后同一次 `gradeChar` 里多出一条
`解锁成就：识字小达人`。断言改成只数那条打卡流水：

```js
expect(ledgerOf(next, DAY).filter((e) => e.reason === '完成：识字')).toHaveLength(1);
```

**这次失败是有用的**：它是「四条打卡路径都接上了结算」这件事的直接证据，
而不是需要绕开的麻碍。改断言而不是改功能。

## 对后续 feature 的影响

- **`STICKER` 仍未开始，且不再阻塞任何东西。** 勋章现在有兑换这个消耗口，
  贴纸是纯粹的收集乐趣，可以独立一轮。它要 140 张的数据包、给纯函数注入随机源、
  加一个收藏册页面 —— 随机源怎么注入是那一轮要拍板的第一件事
  （`now` 那样当参数传，还是让页面传一个 `random()`）。
- **P7 家长端接手三件事**：奖励项的启用与改价（`REWARDS` 目前是常量，不进存档）、
  兑换记录的「家长确认」按钮（`status: 'done'` 此刻只有导入这一个写入路径）、
  `core` 字段的编辑面。**撤销兑换仍然不做** —— 申请即扣勋章的设计前提是
  「说出口就算数」，加撤销要重新拍板。
- **古诗与数学那两轮不必回头改 `ACHV`。** `poem-10` / `math-10` 的判据已经写好，
  读的是 `learningProgress.guoxue?.poems` 与 `math?.games`，两个子键一出现就自动亮起来。
  代价是奖励中心里那两行进度条长期停在 `0/10`。
- **`achievements` 是只增数组，没有回退入口。** `ACHV-13` 钉住了「进度会回落但解锁不撤销」。
  将来若要做「成就重置」，那是家长端的破坏性操作，要单独一条规格与二次确认。
- **首页 toast 的四条分支已经排满。** 再加第五种产出（贴纸？）时，
  `checkedTitle` 的链式三目要改成表驱动 —— 现在还没到那个临界点。
